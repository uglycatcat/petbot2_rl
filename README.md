# PetBot upright：独立从零训练

本项目实现四轮运动接管 → 直线起立 → 两轮遥控 → 前轮落地 → 普通控制。新实验只从随机初始化开始，不加载历史父模型或教师数据；同次受迫中断可恢复完整训练状态。

**当前：第3轮两种子从零完成默认起立和静止循环各32/32；30秒低速循环0/32与32/32，但两者转向响应缺失，尚未通过基本遥控。第4轮修正两轮时间观测、补有界角速度反馈、覆盖30秒训练，并单列按指令分段的基本响应检查。工程验收中，正式批尚未启动，仅GPU2/3。** 既有C58桌面包保持原样，新网络接口不与其混用。

## 当前入口

| 入口 | 用途 |
|---|---|
| `python3 project.py check` | 只读核对用户要求和源MJCF约束 |
| `python3 train.py --dry-run` | 查看配置和源码/模型身份；不导入仿真器、不创建训练产物 |
| `train.py` | 唯一PPO训练入口；新运行随机初始化，`--resume-interrupted`只接受同次中断 |
| `python -m upright.prepare` | 在专用容器内由只读模型生成派生资产；仅在已授权专用GPU2/3容器执行 |
| `evaluate.py` | 显式指定新运行和检查点的固定策略验证，不训练 |
| `export_policy.py` | 新策略单网络ONNX及manifest，不自动更新桌面包 |

基础实现见[第1轮说明](docs/round01_implementation.md)，当前调整与验收见[第4轮执行](../../docs/upright_restart_round04_execution.md)。用户需求见[需求基线](../../docs/current_scope.md)，历史来源见[源码取用](docs/source_provenance.md)和[封存说明](ARCHIVE.md)。没有旧训练入口、自动寻找latest模型或历史目录回退路径。

## 当前配置

`configs/round04.json`固定两种子101/102各1000更新、2048环境。起立和落地沿用第3轮；两轮阶段的时间观测2秒后封顶，实际阶段时钟不变；加入轮距/半径前馈与角速度反馈（增益8，后轮半差速修正限±4rad/s），单个随机初始化actor仍控制共同髋、共同轮速和差速残量，不依赖历史网络或教师。源轮目标仍±25rad/s。两轮训练与评估均覆盖30秒；物理2ms、策略60ms、五帧局部观测。最终交付预算可设10000或更多。

同次运行先学默认起立保持2秒，再学静止完整起落，之后加入连续±0.10m/s、±0.30rad/s与±0.10rad髋初态。每100更新做32项确定性开发检查，连续两次至少80%才晋级；它们不是独立终局验收。进入运动课程后保留20%静止完整循环。能力目标仍为双向连续0–0.75m/s。流程完成与基本遥控分开报告；运动课开发检查还要求前后/左右/停车响应，避免忽略转向仍被判通过。

普通控制不受课程幅度限制；源模型只读，轮目标保持±25rad/s，实测超调单列。共同髋与头耳/前后轮控制约束见[规格](spec/task.json)。课程、奖励、控制和评估分开实现。

## 可复现与验证边界

- 代码、模型及完整配置指纹、独立运行ID、随机初始化证据、优化器、归一化统计、课程和随机状态随检查点保存。只允许同运行、同代码/模型/配置、最新耐久检查点的受迫中断恢复。
- 物理求解器和在途回合不做逐帧恢复；重启时明确复位未完成回合。已完成更新计数不重置、不重复计算。
- `outputs/<明确运行名>/`承载新产物，不扫描`../runs`，不复用旧批次名。发批前仍须固定提交和独立运行副本，并保持仓库内的相对模型布局。
- 工程证据、此前失败及恢复见[第4轮执行](../../docs/upright_restart_round04_execution.md)。正式训练从随机初始化开始，不加载工程短训权重。工程通过与策略能力分别验收。
- 使用现有专用Isaac Lab容器及[依赖声明](environment/requirements.txt)，不在宿主机训练。仅物理GPU2/3：容器单卡隔离并核对UUID，逻辑设备均为cuda:0。周期定时器、goal不启用；有限队列完成/异常事件触发后续分析。

CPU逻辑检查可在已有专用容器内运行：`CUDA_VISIBLE_DEVICES= PYTHONDONTWRITEBYTECODE=1 /isaac-sim/python.sh -m unittest discover -s checks -v`。这些测试不启动Isaac App，不执行PPO训练；ONNX测试只使用临时随机网络。

## 事件驱动运行

`tools/launch_round01.py <明确计划.json>`在干净固定提交和已接受工程指纹下启动两份随机实验；宿主只编排，PPO与评估在专用容器内执行。计划必须指定物理GPU2/3、种子、1000更新、环境数、提交、config配置路径、execution_document执行文档和工程证据，不能搜索历史模型。固定运行副本不随开发代码修改。

启动器保存launch_status/eval_status/eval_finished、日志、退出原因与实际运行PID。独立验证按起立→静止循环→低速混合展开；完全未进入两轮时跳过后两项并交回分析。显存受迫中断只从同一次运行最新完整检查点恢复，代码错误不自动重跑。完成与异常发送一次性事件到已授权原会话；PID退出观察器负责通知缺失检查，不设置周期定时器。
