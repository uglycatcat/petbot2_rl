## 已确认目标

用户已提供四个机器人“摔倒”的默认姿态，固定为 `pose_snapshot_demo` 的 `pose_01`—`pose_04`。建立具有随机探索能力的强化学习环境，让机器人从这些初态反复尝试起立，分别保留能够恢复到四轮着地的策略与动作证据。来源、复位契约及核对结果见[四个固定初态](docs/initial_poses.md)，机器可读清单为[initial_poses.json](configs/initial_poses.json)。

用户已明确已知恢复机制：先让两个后轮同时着地，再利用高摩擦力和瞬间驱动把身体翻正；对应 demo 位于 `robot_controller_demo/`，已定位并静态核对其中的 `pose_recover_demo`。本项目重点是寻找这一机制之外的可行恢复方式，并了解多次探索仍未成功的路径。已知机制、demo 动作与新路线判别方式见[已知方法对照](docs/known_method.md)。

这是独立探索任务，当前没有要求统一为覆盖所有跌倒姿态的通用策略。既有 `recovery_rl_demo` 的分阶段设计与实施顺序不构成本项目的前置条件；旧 recovery、upright、STEP 的训练预算、运行开关和执行授权均不自动继承。

## 探索原则

环境、训练与评估遵循下列原则；实际工程状态以项目交接为准：

1. 将每个给定姿态保存为可重复复位的初态，先检查关节限位、接触和穿透，核对实际仿真初态与用户意图。
2. 按初态分别从随机初始化训练候选策略，使用带随机性的动作采样并根据试验结果更新策略。失败或超时后复位继续尝试；“随机探索”不等于持续施加独立白噪声。先验证固定初态可恢复，再考虑其邻域扰动，分别报告固定初态表现与鲁棒性。
3. 保留不同支撑和翻转顺序的探索空间，不把已知方法写成必经阶段、示范动作或奖励路线。也不通过禁止双后轮接触来强迫求新：最终四轮着地包含这一接触，需区分翻正机制。头部、双耳、轮架或机身接触地面可能是恢复过程的一部分；暂时更倾斜、先滚向另一侧或先建立运动再制动，也可能是候选过程，不能仅凭偏离站姿就提前终止。具体接触和动作约束结合任务单独定义，并始终遵守模型限制。
4. 终态成功判据与训练奖励分开维护。以恢复结果为主要目标，检查姿态、回零、平滑及移动惩罚是否过强，以免设计提前排除可行路径；辅助奖励和时限本身带来的搜索偏向需要记录。
5. 多种子只能提供不同候选，不能保证动作多样性。记录实际滚转/俯仰路线、支撑接触顺序、轮架配合及后轮驱动/制动方式，保留不同动作候选。必要时比较探索强度或鼓励访问不同状态的方案；新奇动作必须另行满足统一的恢复成功判据，重复动作不计作新恢复方式。
6. 每个候选保留配置、源码版本、检查点、视频和实际轨迹。结合成功与失败样本核对机身运动、关节目标与实测、轮速、接触和终态，比较恢复成功率、用时、位移及稳定性。新路线需重复复现，记录它与已知方法的具体区别。

## 如何判读探索结果

- 找到并重复验证不同的成功路线，可以作为当前模型和约束下存在其他恢复方式的证据；不能仅凭参数、用时或随机种子不同就判为新方法。
- 只学到已知路线，说明本次搜索找到该路线，不能证明它唯一。应核查其他动作是否被动作接口、奖励、终止条件或训练时限提前排除。
- 没找到其他成功路线，只能报告“在这四个初态、所用模型、控制范围、探索方案和预算内未找到”。强化学习训练失败本身不能证明其他方式在物理上不可能，也不能外推到所有倒地姿态。
- 失败证据保留实际尝试过的路径、达到的状态及失败位置；区分没有探索到、尝试后失败和实现/资源问题。任何关于某条路径不可行的判断，都需要单独说明依据与适用边界。

## 模型与工程边界

源模型为仓库的 [scene.xml](../../robot_description/mjcf/scene.xml) 及其引用文件，只读，不改变几何、质量惯量或物理参数。当前 MJCF 有五个受力矩限制的可动关节（头、双耳、左右轮架）及两个后轮速度执行器，前轮被动；后轮目标范围为 ±25 rad/s。训练控制接口与伺服配置需在实现时明确，遵守源模型限制。

训练、Isaac 仿真和相应工程验收只在专用容器内执行；遵守共享服务器纪律。训练代码变更须经过适用的容器内 PhysX、短训及检查点重载检查，运行副本固定版本。CPU 检查不能替代仿真与动作验证。

项目在 `demoproj/recover_explore` 独立分支开发，正式发批前提交推送并登记repo清单；main 不重复跟踪嵌套项目的源码与详细文档。宿主编排入口为 `tools/launch_batch.py`，容器工作进程按训练→各检查点原MuJoCo评估→逐姿态选优→独立PhysX/原MuJoCo复验→视频执行，完成后等待本会话审查实际动作再安排下一批。内置显存保护只停止本项目的子进程，不设置外部周期任务。

已知 demo 的项目内对照见[已知方法对照](docs/known_method.md)；历史试操说明见 [固定姿态恢复说明](../../docs/fixed_pose_recovery.md)。demo仅用于对照，不作为训练轨迹；四个指定初态的对照证据保存在本项目artifacts/baseline。
