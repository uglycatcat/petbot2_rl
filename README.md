# PetBot upright：独立从零训练

本项目实现四轮运动接管 → 直线起立 → 两轮遥控 → 前轮落地 → 普通控制。新实验只从随机初始化开始，不加载历史父模型或教师数据；同次受迫中断可恢复完整训练状态。

**当前：第8轮seed101低速/宽髋扩速完整及基本均32/32，seed102静止/低速完整恢复24/32、低速基本22/32，剩余16次物理失败全在落地。第9轮增加训练用短完整循环与随机落地时机，67项CPU与PhysX/短训/恢复/规模/重载、混合采样和60秒对照工程通过，准备GPU2/3各1000更新从零训练。** 既有C58桌面包保持原样，新网络接口不与其混用。

## 当前入口

| 入口 | 用途 |
|---|---|
| `python3 project.py check` | 只读核对用户要求和源MJCF约束 |
| `python3 train.py --dry-run` | 查看配置和源码/模型身份；不导入仿真器、不创建训练产物 |
| `train.py` | 唯一PPO训练入口；新运行随机初始化，`--resume-interrupted`只接受同次中断 |
| `python -m upright.prepare` | 在专用容器内由只读模型生成派生资产；仅在已授权专用GPU2/3容器执行 |
| `evaluate.py` | 显式指定新运行和检查点的固定策略验证，不训练 |
| `export_policy.py` | 新策略单网络ONNX及manifest，不自动更新桌面包 |

基础实现见[第1轮说明](docs/round01_implementation.md)，当前调整与验收见[第9轮执行](../../docs/upright_restart_round09_execution.md)。用户需求见[需求基线](../../docs/current_scope.md)，历史来源见[源码取用](docs/source_provenance.md)和[封存说明](ARCHIVE.md)。没有旧训练入口、自动寻找latest模型或历史目录回退路径。

## 当前配置

`configs/round09.json`固定两种子101/102各1000更新、2048环境。BALANCE增加有符号速度误差0.3秒指数平均的Huber代价（尺度0.05m/s、权重2）；LAND速度代价保持0；移动训练回合的一半随机在4–8秒发起落地，另一半保留30秒，原20%低课程回归不变。每回合仍独立起落一次，不提前暴露未来落地时间给actor；课程每50更新检查一次，仍需连续两次80%基本通过；开发探针仍30秒、独立验证仍60秒，真实保持条件按对应回合时长判定。落地控制仍继承入口实测速度，保持原动作/髋归零/交接。两轮奖励只用于训练，不进入策略观测或控制器。两轮控制参考线加速度限0.5m/s²、角加速度限1.5rad/s²；原始请求独立保存和评分，参考进入策略观测、反馈和跟踪奖励。大范围指令停留时间至少覆盖一次最大反向参考变化再留1秒，0.75m/s阶段为4秒。进入落地保留最后策略参考，实际运动继承和普通控制交接保持。起立和落地动作沿用既有机制；两轮阶段的时间观测2秒后封顶，实际阶段时钟不变；加入轮距/半径前馈与角速度反馈（增益8，后轮半差速修正限±4rad/s），单个随机初始化actor仍控制共同髋、共同轮速和差速残量，不依赖历史网络或教师。源轮目标仍±25rad/s。两轮训练30秒、独立评估60秒；物理2ms、策略60ms、五帧局部观测。最终交付预算可设10000或更多。

同次运行先学默认起立保持2秒和静止完整起落（每50更新检查），再学运动课程（每100更新检查），连续两次32例至少80%才晋级。两轮训练30秒，独立验证60秒。每个能力阶段分别定义两轮速度/角速度、接管线速度、共同髋初态；先从±0.10m/s、±0.30rad/s、接管±0.10m/s和髋±0.10rad开始，再扩大两轮运动与髋初态。完整阶梯见配置，最高两轮双向0.75m/s是训练目标，不代表已达能力。运动课程保留20%较低难度回归，预算最后一次检查不晋级到尚未训练的阶段。

流程完成与基本遥控分开报告。基础协议保留；高阶段增加前后满幅直行及中间速度、镜像转向序列。请求幅度、源目标约束、实测响应和当前已训练课程分别记录，不能用宽松基本响应计数宣称已达0.75m/s。

普通控制不受课程幅度限制；源模型只读，轮目标保持±25rad/s，实测超调单列。共同髋与头耳/前后轮控制约束见[规格](spec/task.json)。课程、奖励、控制和评估分开实现。

## 事件驱动运行

`tools/launch_round01.py <明确计划.json>`在干净固定提交和已接受工程指纹下启动两份随机实验；宿主只编排，PPO与评估在专用容器内执行。计划必须指定物理GPU2/3、种子、1000更新、环境数、提交、config配置路径、execution_document执行文档和工程证据，不能搜索历史模型。固定运行副本不随开发代码修改。

启动器保存launch_status/eval_status/eval_finished、日志、退出原因与实际运行PID。独立验证按起立→静止循环→低速混合展开；完全未进入两轮时跳过后续；若已训练更高阶段且低速物理完整至少26/32，再增加当前能力阶段验证，其余显式记为跳过。显存受迫中断只从同一次运行最新完整检查点恢复，代码错误不自动重跑。完成与异常发送一次性事件到已授权原会话；PID退出观察器负责通知缺失检查，不设置周期定时器。

每个控制周期在策略观测前调用`Controller.update_motion_reference()`一次；观测用`motion_command()`，日志分别记录`requested_command`、`control_reference`、`effective_command`及实际关节目标和机体运动。普通控制按源范围执行，不受两轮加速度限制。
