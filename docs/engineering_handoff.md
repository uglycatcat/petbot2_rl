# PetBot 自恢复工程实施说明

更新日期：2026-10-12。本文用于后续工程交接；需求以 [当前需求基线](current_scope.md) 为准，仓库入口见 [README](../README.md)，接手摘要见 [AGENTS](../AGENTS.md)。以下训练设计是待验证的实施建议，不是已完成的实现或实验结论。

## 背景与当前状态

本仓库可在任意位置检出，已独立于其他项目，程序不依赖宿主机绝对路径。训练全部在训练服务器上进行，桌面机只在最后用 MuJoCo 等检验训练效果（两台设备的判断方法见 [AGENTS](../AGENTS.md)）；参考项目与其产物放在 `reference_project/` 下，不进版本管理。

PetBot 在平地运动时可能被推倒或从高处落下。目标是从多样倒地状态，通过预训练策略流畅恢复到模型默认站立构型并保持稳定。用户已有 Isaac Gym + PPO 双轮足运动训练经验；当前重点是选择可复用框架、构造有效训练任务并跑通 MuJoCo 闭环验证。

已有能力基础：默认轮足构型可静稳定站立，无需单独训练站立策略；用户已验证通过几个固定姿态的转换可从任意摔倒姿势恢复站立（测试细节尚未归档）。RL 的目标是在此基础上学习更自然、连贯、平滑的恢复动作。训练采用 5 路位置目标 + 2 路速度目标的混合输出，且不依赖预先准备的参考动作流或示范轨迹；固定姿态恢复经验不构成现成的模仿学习数据。完整需求见[已有能力与强化学习的目的](current_scope.md#已有能力与强化学习的目的)。

第一阶段验证算法与仿真链路，不以实机电机辨识、PWM 建模或 sim2real 成功为前提。真实执行器的目标接口为五路位置闭环和两路后轮速度闭环；仿真同样采用目标位置 / 速度接口。

现有资产是 `robot_description/mjcf` 和 STL（**只读**，禁止修改模型与物理参数）。尚未建立 Isaac Lab 资产、PetBot 环境注册、恢复奖励、策略导出或 MuJoCo 策略推理程序。所有新增训练工作在本仓库内进行；本文中的路径均相对仓库根目录。

## 模型约束与资产基准

这不是常规四足：头部、双耳和两侧轮架可动，后轮主动、前轮被动。恢复过程可能依靠头耳支撑、身体滚转、轮架改变支撑和后轮转动协同完成。不能直接继承“非足端接触即失败”的运动任务设定。

当前模型有浮动基座和 9 个旋转关节，7 个受控通道。MuJoCo 加载结果为 `nq=16, nv=15, nu=7`。五个有界关节使用 motor，两个后轮使用 velocity；策略需要的原生位置伺服仍是后续工作（早期键盘 demo 曾用外部位置 PID，该 demo 已废弃）。

建议以如下关节名明确接口，最终顺序写入同一份训练 / 推理契约：

| 建议动作索引 | MJCF 关节名 | 类型 | 单位 |
|---|---|---|---|
| 0 | `head` | 位置目标 | rad |
| 1 | `left_ear` | 位置目标 | rad |
| 2 | `right_ear` | 位置目标 | rad |
| 3 | `left_frame` | 位置目标 | rad |
| 4 | `right_frame` | 位置目标 | rad |
| 5 | `left_rear_wheel` | 速度目标 | rad/s |
| 6 | `right_rear_wheel` | 速度目标 | rad/s |

`left_front_wheel`、`right_front_wheel` 保持被动，不能因关节列表包含它们而意外增加动作通道。五个位置目标的零点、限位来自当前 MJCF，不能借用其他机器人的默认关节角。

默认站立是模型加载构型的基准，不是必须返回相同世界坐标。应保存本体姿态、五关节参考角、站立时接触关系和静置后的高度范围；水平位置和 yaw 暂不约束。自由轮的绝对转角不作为终态目标。默认初始化与接触静置可能有少量差别，成功容差需在资产核对后确定。

资产转换验收包括：

- 关节轴、方向、零位、限位和 STL 缩放；头耳与前轮的斜轴不能被简化成未经验证的标准轴。
- 质量、惯量、质心和浮动基座；导入器可能重算惯量或改变 link 合并方式，需要与 MJCF 对照。
- 碰撞外形、碰撞过滤、地面接触、被动轮阻尼；保留能影响翻身的头耳和身体接触特征。
- 前轮 / 地面实际摩擦组合规则；MuJoCo 与 PhysX 的材料混合方式不同，不能只比较单个 friction 数字。
- 保持当前 MJCF 为物理参数来源；本次不修改摩擦、执行器、质量或控制器代码。

## 框架复用方式

按 2026-10-12 明确的“恢复任务接入代码成本优先”标准，建议先评估 `WBC-AGILE / StandUp-T1-v0` 作为恢复任务与训练底座，`robot_lab / Go2W` 作为位置 / 速度 action 分组参考。此建议尚未完成复现或最终选型，详见[参考项目选择建议](reference_selection.md)。复用已有恢复流程和训练入口，替换资产与机器人专用配置；不把更换 Docker 环境作为主要选型负担。

`WBC-AGILE` 重点看 `stand_up` 的倒地状态数据集与课程实现；它当前使用的 Lab 版本不同，移植相关概念和必要函数时需适配 API。`getup_gym` 提供轮足恢复的力辅助与分阶段思路；`HumanUP` 提供先发现动作、再优化平滑性的路径。具体入口见 [参考项目索引](../reference_project/README.md)。

普通 locomotion 配置中的速度命令、步态、足端腾空奖励、身体碰撞终止、早期强姿态惩罚，不应未经审查直接继承到恢复任务。无需单独训练站立策略，首版也不要求先训练一套行走策略。参考方法必须能在无参考动作数据的条件下学习恢复，不能把依赖示范轨迹的模仿学习、AMP 或运动捕捉数据作为训练前提。用于初始化的倒地状态库只提供初态，不是参考动作流。

## 训练与推理接口

建议使用归一化 7 维动作，分别映射到五关节位置与两后轮速度。位置采用默认角偏移或全关节区间映射，需在单关节试验后固定；不能直接照搬运动任务的小 action scale，导致探索范围无法覆盖翻身动作。映射、限幅、滤波必须训练与推理一致。

Isaac Lab 中使用 `JointPositionActionCfg` / `JointVelocityActionCfg` 与 `ImplicitActuatorCfg`；五个位置通道设有限刚度、阻尼和力矩上限，后轮设速度驱动。MuJoCo 对应原生 position / velocity 伺服。控制输出仍为目标量，不把策略输出或外部自写 PD 的结果当成力矩 action。两种引擎的 drive 数值不必相等，应通过响应试验校准到相近行为。

第一版 actor 候选观测为基座角速度、投影重力、五个受控关节相对角、相关关节速度和上一时刻动作。基座线速度、接触、真实高度等可作为 critic 的额外状态；具体 actor / critic 维度与历史长度待实现时确定。轮角无限累积不宜直接作为角度误差输入。实机可读关节角度、速度和力矩，但本阶段不将未确认的额外传感器假设绑定到策略接口。

同步记录：

| 项目 | 需要明确的内容 |
|---|---|
| 观测 | 字段顺序、单位、坐标系、缩放、裁剪、历史排列、归一化统计 |
| 动作 | 名称顺序、各通道 scale / offset、限幅、目标保持与滤波 |
| 时间 | 物理步长、策略频率、decimation；当前 MJCF timestep 为 0.002 s，训练频率尚未确定 |
| 状态 | quaternion 顺序、世界 / 本体速度、重力投影、左右轮正方向 |
| 伺服 | 位置 / 速度目标、增益、力矩限制、速度限制与饱和行为 |
| 导出 | 网络、归一化器、循环网络状态（如使用）、模型 / 配置版本 |

## 恢复任务设计

### 初始化与状态覆盖

先构造平地静止倒地集合：侧躺、仰躺、趴倒，以及头耳 / 轮架处于不同构型的状态。随机根姿态和关节角后，应通过抬升、自由落下与沉降生成物理有效样本，过滤穿透、数值异常与重复样本；直接随机欧拉角并放在固定高度容易产生穿地状态。

初期使用按姿态分层的倒地库提高样本效率，同时保留一定站立附近样本学习稳定保持。后续加入推倒、不同落高与带残余速度的状态，避免只会从静止倒地库恢复。状态库绑定模型版本，资产改变后重新核对或生成。

### 奖励与课程

首版采用常规 PPO，先在固定物理参数下验证可学习性。主奖励围绕正向直立程度、接近站立高度、恢复进展与成功保持；接近直立后再加强默认关节构型、低轮速和低基座速度约束。

**不能照搬参考项目的塑形与课程**：PetBot 本来就能站住，而轮足翻倒起身类参考项目默认还要解决"站住"的问题（见[需求基线](current_scope.md)）；它们为学会站立付出的那部分（高度 / 姿态塑形、ED-CW 类课程、辅助力）对 PetBot 未必需要，是否采用要按本任务重新判断。

直立指标要区分正立与倒置：仅使用投影重力的 x/y 平方惩罚，会把仰倒且躯干水平的状态误判为同样“平”。应使用带方向的竖直轴对齐量，并结合支撑 / 高度和终态条件检查。

关节 / 力矩限幅始终生效。动作变化、能耗、接触冲击等正则从适度权重开始；若一开始强迫所有关节保持默认角，可能抑制必要的翻身。先学会恢复，再提高平滑和稳定标准；课程不能以最终仍存在的外部助力掩盖能力不足。

如果 PPO 在某些倒地类别长期无法探索到成功，可引入逐步衰减的虚拟辅助或教师策略，参考 AGILE / FTSR。辅助是备选探索手段，不是默认必须增加的复杂度。最终评估严格关闭辅助。

论文依据：[轮足动态奖励塑形](https://arxiv.org/abs/2506.05516)、[HumanUP 两阶段恢复](https://arxiv.org/abs/2502.12152)；具体奖励权重和课程边界仍需 PetBot 实验确定。

### 终止与评估

头、耳、身体触地不自动判失败。训练可因超时、无效物理状态或明确的场景边界终止；“无进展”终止是否启用要谨慎验证，避免截断必要的准备动作。

成功要求在给定姿态、构型、高度和速度容差内持续保持一段时间，不以瞬间经过直立姿态计成功。恢复时间上限、保持时间和阈值尚未设定。最终固定测试集与随机种子，按侧躺 / 仰躺 / 趴倒 / 动态推倒 / 落地分别报告成功率、耗时分布、动作变化、峰值力矩或冲击、恢复后稳定性与失败类型。

动作自然性需结合恢复视频与平滑性指标评价，关注动作连贯性、突变和多余振荡；具体指标及阈值待定。已有固定姿态恢复能力与 RL 动作质量分别记录，不能用前者代替策略评估，也不能仅凭恢复成功宣称自然性目标已达成。

泛化逐步覆盖未见初态、不同摩擦、质量 / 质心小扰动和有限控制时序偏差；随机化范围来自模型敏感性实验，先不无限扩大。训练与 MuJoCo 使用相同测试定义，评估中禁用教师、辅助力和训练专用特权输入到 actor 的通道。

| 阶段 | 产物 | 完成判据 |
|---|---|---|
| 上游复用验证 | 所选参考项目的专用容器与实际版本记录 | 上游已有任务可短训、保存及加载；本阶段再固定兼容版本 |
| 模型与控制 | Isaac Lab 资产、7 维动作、两引擎伺服配置 | 单关节 / 轮速方向正确，默认站立、落地与接触行为合理 |
| 任务最小闭环 | 静态倒地集合、观测、奖励、终止、成功检测 | 随机 / 固定目标试验无数值错误；成功判据无倒置假阳性 |
| 基线学习 | PPO 配置、检查点、固定评估集 | 各类倒地分别评估，报告真实结果后再定是否需要辅助课程 |
| 泛化与平滑 | 扩展状态分布、课程和随机化对照 | 评估关闭辅助，未见状态与平滑性改善可复现 |
| sim2sim | 导出策略、MuJoCo 推理入口、配套配置 | 同一策略在 MuJoCo 完整恢复并稳定保持；记录差异及失败案例 |

MuJoCo 迁移先用固定观测比较网络输出，再对照伺服阶跃响应，最后进入闭环恢复。共享观测 / 动作契约只能减少差异，不能自动消除 PhysX 与 MuJoCo 的接触、摩擦和驱动差异。

## 自动恢复的接管与退出

先验证倒地初态到站立保持的策略闭环，再接入演示的恢复模式。候选流程为正常控制 → 持续翻倒检测 → 恢复策略 → 站姿持续达标 → 稳定保持或交还手动控制。进入 / 退出采用滞回和保持时间，阈值待定；切换时对齐目标量、观测历史和控制器状态，避免指令跳变。

首版重点是触地后的恢复，覆盖跌落后的残余速度；空中主动姿态控制不是首版必做项。恢复超时或数值异常时记录失败原因。静态倒地恢复、动态推倒和跌落恢复分别评估，不能以一类成功替代其他场景。

## 后续需要落定的项目

任务实现前确定控制频率、伺服增益、目标范围、模型转换流程和成功定义；首轮短训后确定奖励权重、倒地采样比例、网络结构以及是否需要辅助课程；导出前确定推理格式、归一化和恢复结束后的站立保持方式。

当前不要求实机参数辨识，也不承诺某一训练时长或成功率。模型、算法配置与固定评估结果共同构成后续决策依据。
