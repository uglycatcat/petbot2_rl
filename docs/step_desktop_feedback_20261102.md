# Step桌面反馈与显示性能修复（2026-11-02）

用户桌面实测反馈：机器人可完成登台运动，但登台后持续行驶不停车；连续两次抬头，第一次无效、第二次前轮才搭上平台；MuJoCo窗口帧率低。这是对实际视觉动作的确认，完整停稳和单次抬轮尚未验收通过。发布的默认仍为第14轮seed71；第16轮在GPU0/1训练，不能把桌面旧包效果与当前训练混淆。

## 训练侧新增要求

一次登台，两前轮各只允许一次真实离地，直接越沿落到平台；台前试抬回落再抬、落顶后再抬均不合格。实现须用2ms接触与轮几何、带时间确认的状态转换，分别记录离地/落地次数和时刻，过滤接触抖动；不能只读髋角峰值或曾离地布尔量。源码核查确认旧`relift_cost`只作用于`front_landed`之后，确实遗漏台阶前的无效动作。

当前第16轮`5e1e03e`继续；本次只将新要求提交到demo文档`6bc40eb`，没有改动训练逻辑、配置或固定运行副本。下一轮须根据第16轮真实结果，实施并验证离地计数、重复动作约束和完整验收，再重新从零训练。自主短行后零轮请求与实际停稳仍为第一优先。当前批次`agent_review.json`及campaign反馈记录显式要求事件处理时落实；不能用规则停车替代策略成绩。

## 本次已交付的显示修复

独立sim2sim分支`771d7a5fdfd2cddbbfef933775325b6abd236d01`：物理和策略在工作线程执行，窗口只读取完整状态副本并使用独立MjData绘制。空间键/R送入同一物理线程按顺序处理；真实窗口验证两次开始、两次完整复位有效。物理步长2ms、策略周期20ms保持，不丢弃物理步；慢机器可以低于实时，画面展示实际刷新率和仿真速度。默认绘制目标60 FPS，可用`--render-fps`调整；昂贵阴影/反射关闭，源机器人模型/物理和策略不变。

另优化固定3维向量运算与详细前轮网格的内存布局，仍使用每一个源几何顶点。1200步传感器随机输入含静止/复位，与旧实现逐项一致；3秒150控制帧（1500物理子步）的完整动作、关节、运动、估计等记录逐项一致，异步GUI的轨迹前缀也完全相同。源机器人物理数组、初始静止、52帧重置复现和实际X11按键检查通过；运行时没有Torch。

有限同机Xvfb/Mesa软件渲染对照：旧版约1.60 FPS，新版约10.68 FPS；帧间隔中位625→68ms，95百分位668→185ms。新窗口循环6.03秒墙钟推进5.90秒物理。服务器软件渲染受共享负载限制，不保证桌面60 FPS，用户仍需更新后复测。首轮并行软件渲染键盘检查超时、受干扰中间性能样本保留且排除；最终串行窗口按键检查通过。性能数据不作策略能力改善。

源策略仍不会合格停车，重复动作尚未通过新训练修复。源模型不变、训练未暂停或重发，正式训练预留目录仍为空。
