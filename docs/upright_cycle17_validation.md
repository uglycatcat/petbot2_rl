# 第十七批后的固定策略验证（2026-10-27）

第十七批局部坐标组在180秒小范围测试中没有失稳，但额外PPO没有普遍提高基本功能；详见[终局](upright_cycle_batch17_results.md)。本轮只做固定策略验证与交接诊断，不启动第十八批训练，不修改任务、模型、奖励、控制接口或成功判据。

固定工具版本`9fcc3d2`，`train_cycle.py`和`upright/`与已验收`a64c755`完全相同。计划见[JSON](experiments/upright_cycle17_validation.json)，状态入口`runs/_upright_cycle17_validation/`。执行器拒绝旧状态重复启动，核对固定源码及检查点哈希，所有子任务只能`--evaluate`或`--probe`。已有GPU任务验收继续有效；新增纯记录探针仍需与原轨迹逐项对照，不能假设没有副作用。

## 七项任务

1. 第十七批B42/199，在原±0.30 rad车架、60秒、种子20261020条件复现，增加复位前车架实际关节、初始/落地目标及地面保持计时。原结果为42/64交接、7次起立失败、15次交接超时；新增记录必须复现原结果和有效轨迹。
2. 未微调第十六批B43迁移到分阶段局部编码，与第十七批B46/199，分别在新种子20261130、20261131各做64回合180秒小范围遥控，共4项。
3. 这两个候选再各做一次±0.30 rad车架、60秒诊断，录制相同交接字段，共2项。用途是划清初态/落地边界，不将开发种子的结果当作独立大范围成功率。

仅初始化参数变换的候选通过`--initialize-cycle-from --probe`执行，没有PPO；训练候选通过原检查点`--checkpoint --evaluate`执行。两者均保留位置/轮速输出、原始指令和基本遥控判据。

## 下一步决策

先确认记录探针复现，再区分真正起立/两轮失败、已经落地但车架未对齐的交接超时、基本遥控不足。若后者成立，考虑在持续四轮稳定接触后平滑交还普通控制，由普通控制完成车架对齐；这需要单独GPU对照和稳定交接验证，不能直接删掉条件填高成功率。起立范围不足仍需独立处理。

新种子小范围验证支持后，优先保留稳定候选并准备MuJoCo闭环，不再围绕旧瞬时精度重复训练。是否继续PPO取决于定位出的实际缺陷；扩大范围与仿真迁移均未完成，自动化任务尚未宣告收敛。
