# 环境与验证设计

2026-11-17，首版实现与工程验收已完成，尚无原始MuJoCo验证成功的RL策略。

## 任务与控制

四个录制初态各对应一个独立actor/critic，权重完全分离。每路同时运行四组，GPU2/3各两路，比较两种探索强度和两个随机种子；每个组从随机初始化开始。初始姿态固定，不使用站姿课程、教师或已知demo轨迹。

七个控制自由度是头、双耳、左右轮架五路角度目标和双后轮速度目标。A方案直接输出归一化目标；B方案输出目标增量：每20 ms把上次归一化目标加上0.12×本次有界动作，并裁剪到[-1,1]，对应后轮每步最多改变3 rad/s。上一目标包含在观测中，保持马尔可夫接口。B的初始策略均值是零增量，没有预设恢复动作。两方案分别配置熵系数0.02/0.06用于探索覆盖，不把差异解读为单一变量的因果比较。角度目标映射源模型关节范围，后轮目标限定±25 rad/s；前轮被动。源MJCF的力矩、阻尼、干摩擦、惯量与关节范围作为适配依据；位置伺服初值沿用恢复demo的KP `[8,4,4,12,12]`、KD `[0.35,0.04,0.04,0.35,0.35]`，这是控制器参数，不是已测实机增益。

开发候选C保持绝对目标接口，另设`noise_rho`。tanh之前的条件均值为`actor(obs) + rho*(atanh(previous_target)-atanh(home_target))`，条件标准差为`sigma*sqrt(1-rho^2)`。上一目标已经包含在观测18:25维，没有隐藏噪声状态；采样、PPO似然和确定性复验共用该条件均值。rho=0时与原接口完全相同；rho>0只支持绝对目标，检查点保存此参数。初始网络近似home均值，因而随机目标具有跨时刻相关性；学习后不保证固定相关时长。此候选不修改第二批冻结代码，是否采用以完整门槛和实际动作结果决定。

物理步长2 ms，策略周期20 ms，每回合16 s。初版成功条件：机身倾斜小于25°；四轮各自在一个控制周期至少80%的物理采样中承受大于0.05 N的向上力；非轮身最大净接触力小于0.5 N；线速小于0.15 m/s、角速小于0.4 rad/s、两个后轮实际速度均小于1.5 rad/s；这些条件连续保持0.5 s。不要求头、耳或轮架回默认角。门槛是当前工程选择，视频和原模型验证仍须复核实际四轮着地，不能凭阈值漏洞认定成功。

成功、非有限状态、基座低于地面0.1 m或离初始水平位置3 m时结束；其他倒地接触不提前结束。16 s超时作为有限时域终止，剩余时间进入观测。

项目内部、快照、奖励和原MuJoCo统一采用wxyz四元数；Lab 3的根状态API采用xyzw，必须在写入和读取边界显式转换。每次训练及PhysX重载启动时，将四个起点每个刚体的实际世界位置/方向与原MuJoCo前向运动学对照（位置误差≤0.1 mm、方向误差≤0.001 rad），单纯根数组相等不能替代这项验证。

观测34维：体坐标重力、角速度、五位置关节角和速度、双后轮速度、前一动作、线速度、四轮接触、基座高度和剩余时间。部分观测取自仿真真值；本任务是构型探索，不宣称实机传感器接口已实现。

奖励以恢复为主，成功奖励40，失败惩罚5，每步代价0.01，四轮支撑和稳定分别有小幅辅助奖励。姿态和接触采用势函数差 `2*(gamma*Phi_next-Phi_previous)`，终止状态势函数置零；不规定翻滚方向、固定阶段或双轮发力路径，不惩罚单纯偏离直立。折扣gamma=0.998；GAE lambda=0.97。其他PPO设置以运行config.json为准。

C候选另有小幅直接直立奖励`upright_reward*(up+1)`，系数限制在0—0.005。满16 s的最大额外折扣回报约3.99，成功奖励仍40。该项为接近翻正但尚未四轮着地的回合提供非零目标差异；它会偏向较直立状态，属于明确记录的搜索偏向，不能解释为保持势函数策略不变性的项。A/B冻结方案的系数仍为0，继续作为不同搜索偏向的对照。

## 物理适配与局限

训练采用容器内Isaac Lab 3/PhysX。仅复用1104工程的模型解析和资产转换基础代码，恢复任务、奖励、策略与训练循环独立编写。训练不加载其他项目权重。

派生资产位于本项目artifacts：从源MJCF/STL复制生成，源目录只读挂载。碰撞采用Convex Hull，对应MuJoCo网格凸包语义。轮与机器人其他部件的碰撞被过滤，保留自碰；地面接触有效滑动摩擦配置为后轮1.5、其他部件0.1，原MJCF地面1.5与后轮1.4在无优先级覆盖时取较大值，前轮及显式接触对为0.1。

PhysX材料绑定不能完整表达MJCF接触对表：非轮部件自碰摩擦、扭转摩擦和软接触求解仍有引擎差异。材质适配在导入器进程结束后重新打开序列化USD实施，避免命名变化后的schema缓存漏掉碰撞体；同时审计十个有效绑定与PhysX运行时shape属性。相同摩擦类别复用材质，并在初始化前校验64K容量。所有候选必须在只读原始MJCF中独立复验；PhysX成功不等于原模型成功，更不能据此宣称物理不可行。MuJoCo复验使用demo同样的implicitfast数值积分器，几何、质量、摩擦、执行器限幅不变，也保留source积分器对照选项。

原模型2 ms步长下，悬空后轮在归零目标后存在逐物理步正负交替的数值振荡，20 ms记录可能混叠成单向转速。`tools/check_native_servo.py`复现并比较2/1/0.5/0.25 ms，后两者消除此例振荡。因此原MuJoCo评估另提供`--physics-dt`作积分分辨率对照；它只改变内存中数值积分步长，源文件、物理参数、20 ms策略周期和成功阈值保持一致，报告同时保存源/实际步长。原2 ms结果保留作对照，候选动作还须检查较细步长的一致性，不能用单次步长的成功或失败替代结论。当前开发版另存每个物理子步的后轮速度与执行器力矩，便于识别混叠。

## 工程与交付

- engineering.py：真实GPU复位、静止成功判据、随机目标及轮速反转的动态检查，保存轨迹。
- train.py：分组PPO、TensorBoard、逐初态成功计数、原子检查点和状态文件；同次中断恢复要求代码与模型摘要一致。
- 训练动作证据：默认保存每100更新窗口、每初态前两条成功回合的实际绝对目标序列，覆盖全部20 ms动作，自动复位前截取；记录初态、源模型/代码摘要和环境编号。仅标记为待独立重放的训练成功，不能直接当作原MuJoCo恢复结果。分段目录避免中断恢复覆盖历史证据。
- evaluate.py：独立进程加载检查点，在PhysX中以确定性动作评估四个精确初态及并行副本，保存完整轨迹。
- evaluate_mujoco.py：原始MJCF独立复验或已知demo对照，保存接触/关节/控制/机身轨迹和四画面MP4；当前开发版另存ground_force，仅含对地接触。
- tools/analyze_trajectory.py：对原MuJoCo轨迹生成支撑时序与采样驱动力摘要，拒绝用含自接触的净体力代替地面支撑；机制归类仍须审查完整动作。
- tools/plot_trajectory.py：生成四初态姿态/轮接触/轮速总图和各初态关节目标—实测图；图中红色区域为越界后的无资格时段。
- tools/check_native_servo.py：原模型悬空后轮驱动后归零的积分分辨率检查，保留逐物理步证据。
- tools/check_witness_capture.py：真实PhysX合成站立回合验证完整动作截取、末步与自动复位边界，不构成倒地恢复能力证据。

评估以累计有效标记排除越界或非法状态之后的成功，首次违反边界的时间单独记录。为保留失败过程，评估继续记录完整16 s轨迹；它不代表越界后仍有训练资格。原MuJoCo记录策略目标、执行器输入、实际力矩、关节与接触力。

固定初态的确定性副本不代表随机初态泛化率。新机制按翻正阶段支撑与驱动轨迹判读，不能由动作文件名、种子或汇总成功率推断。
