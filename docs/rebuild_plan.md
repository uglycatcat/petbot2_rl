# 恢复有效基础并完善从零训练路径

用户已明确需求和目标效果，当前重点是训练代码恢复、改造与迭代效率，不再把需求澄清或全盘重设计作为前置。早期有效代码可核查后复用；新工程从零学习尚待验证。第26批保持取消，本次澄清未重新启动训练。

## 必须首先修正的组织问题

过去的完整循环效果依赖历史模型积累；后来scratch入口仍委托多代完整循环实现，并同时改变网络和控制周期。其工程通过只能证明运行链路，未证明冷启动学习有效。应保留早期有效的实现经验，移除历史权重依赖；从零复验其效果，不把旧策略成功率当作新训练结果。此前将全部旧代码排除的处理范围过大，现已纠正。

## 重建顺序

1. **恢复经核查有效的早期基础。** 对照固定代码和真实训练来源，优先复用有效的模型接口、观测/动作、起落状态流程及训练实现，移除父网络与历史权重依赖。已合适的网络、控制周期和伺服不为重构而更换；仅改造成零训练或满足最新需求所必需的部分。静止v5提供从零起立证据，完整循环第17批提供流程效果证据，但后者已有父策略依赖，不能整版当作从零基线。
2. **建立从零起立学习门槛。** 在真实默认四轮构型、静止条件下，从随机网络学习前轮离地及后轮支撑。先检查奖励是否鼓励实际进展、有无原地获利及终止漏洞；独立检查离地、进入两轮和保持，不能只看总回报。默认构型用于第一阶段训练，不能作为最终能力范围。
3. **在同一训练中扩展完整循环。** 明确起立、持续平衡、前轮落地和交接的学习课程；阶段变化属于同一次训练内部机制，不能依赖外部历史检查点。最终仍按完整调用验收，课程阶段不得降低最终要求。
4. **扩展初态与运动能力。** 分别探索共同髋初态、接管速度、连续双向直线、转向与镜像联合运动；保留已掌握能力，验证必要调整及直接起立。双向0.75m/s目标不下调。
5. **完善泛化与部署。** 设计有依据的初态、指令、观测噪声和外部扰动，不伪造测得的随机范围；涉及物理参数变动的方案必须先明确允许范围，当前不作为已授权改动。ONNX数值检查后，再做MuJoCo闭环和用户体验验收。

## 训练与验收约束

当前demo以每份1000更新开展较短、多批次迭代，优先尽快形成可用效果；工程短训单列。最终交付的从零训练预算可高于1000，包含10000或更多更新，由收敛与能力验证决定，不设1000上限。各独立实验从随机初始化开始，只允许同次受迫中断恢复网络、优化器、课程和随机状态，不将重新运行后的物理回合冒称逐帧恢复。批次和GPU由实测资源决定，不要求短时间跑完大型训练。

需求已经明确，历史源码与经验的筛选、复用范围及训练方案由agent负责判断，不再作为需要用户补充需求的问题。区分有效实现经验和历史网络权重，历史权重初始化禁令保持。

学习门槛和最终门槛分别报告：前轮离地、真实两轮支撑、持续控制、正常落地交接和异常退出各自计数。独立评估必须覆盖请求/执行/实测、成功及失败轨迹、低速回归、镜像动作、中间速度与端点、共同髋初态。具体容差、持续时间和统计样本量预先定义，尚未定值；不沿用旧瞬时精度作为主要否决条件，也不以宽松阈值掩盖达不到0.75m/s。

当前先恢复和整理训练基础，不重新讨论已经明确的需求。训练保持暂停；第26批及历史队列不自动恢复。完成事件不会授予新的训练权限，周期定时器与goal始终禁用。
