# 重建的工程边界

目前仅实现需求规格读取和源模型只读核查。下面为新工程的职责设计，尚未实现仿真训练模块；不把目录或接口设计当作功能完成。

| 层 | 职责 | 不应承担的职责 |
|---|---|---|
| 模型与资产 | 从只读MJCF派生仿真资源，核对轴向、惯量、限位、力矩、接触和前轮被动属性 | 修改源模型以提高分数 |
| 控制接口 | 普通控制、共同髋位置和左右轮速接口、物理限幅、连续交接 | 限制普通控制来掩盖策略能力不足 |
| 单次调用状态 | 接管、起立、两轮、正常落地、中断退出；明确每次转换原因 | 调用父策略、决定奖励或代替真实姿态 |
| 观测与动作 | 清晰定义可部署传感量、坐标、历史、动作单位与采样周期 | 将仿真独有接触力混入部署前提 |
| 奖励与课程 | 在同一随机初始化训练中提供可审查的学习信号和难度调整 | 改写最终成功定义、导入旧策略或教师数据 |
| PPO与恢复 | 保存网络、优化器、课程、随机状态及唯一运行身份 | 跨实验加载模型伪称从零训练 |
| 独立评估 | 用真实轨迹核对功能、稳定性、对称性、边界与失败 | 以训练回报或退出0替代验收 |
| ONNX与MuJoCo | 对齐输入、输出、时钟、状态与控制交接，再做闭环体验 | 以网络数值一致替代sim2sim通过 |

训练端和MuJoCo端共享清晰的接口规格；奖励、课程和独立评估分开实现。状态机采用明确组合，避免继续叠加历史任务继承链。部署所需状态与仿真奖励专用状态分别声明。

未来只设一个受支持训练入口`train.py`。计划、配置、来源、环境和产物均关联同一次运行；工程验收、正式训练、固定评估分别标识。按职责恢复或改造经核查有效的早期源码；明确移除历史权重依赖，验证随机初始化路径，不能靠旧模型让入口“恢复可运行”。需求已清晰，架构整理服务于尽快恢复训练，不作为重新讨论需求的前置工作。
