# 架构与实施顺序

## 当前已实现

标准库Python框架：严格配置读取、只读源模型限位和XML/STL指纹、两维动作映射、一次性地形锁存、actor输入构建、独立完成状态机、CLI检查和合成输入回归。无其他demo导入、历史产物路径、模型权重或训练数据。不存在已训练策略。

当前接口是单机器人参考实现；后续向量化Isaac环境需要保持同一契约并做等价检查，不能把这些标量类直接当作已具备GPU并行训练能力。

```text
初始地形包 ── 每回合一次锁存 ─────────────────┐
IMU/编码器 ── 自身状态与运动估计（待实现） ──┼─ actor输入 ─ 策略（待实现）
上一动作 ───────────────────────────────────┘                 │
                                               共同髋角/共同轮速
                                                            │
只读源模型 ── 派生资产/位置伺服（待实现） ←─ 左右同步目标 ─────┘
                         │
                   PhysX场景（待实现）
                         ├─ 自身传感样本 → 估计器
                         └─ 真值/接触 → 奖励（待实现）与独立验收
```

`interfaces.py`只定义估计器/后端协议，不用假的轨迹替代仿真。`evaluation.py`消费后端证据，当前单测通过只表示顺序约束可检查；接触分类、支撑判断与抬轮越沿证据尚未接通。

## 后续实施顺序

1. 在step自己的场景层加载/转换只读模型、生成平台，验证源关节/执行器/摩擦/碰撞与默认姿态。派生资产放忽略目录，不更改`robot_description/`。平台位置基于复位后质量加权整机COM，不使用base位置替代。
2. 在专用容器内验证PhysX接触几何、同步目标、伺服力矩、被动前轮及头耳保持；观察正常顶面接触、立面/棱边碰撞、后轮滚上和真实失稳。采集全部物理子步事件。先确认源物理下的可达性，不通过修改机器人模型解决学习困难。
3. 实现IMU/编码器通路与自身运动估计。用真值仅做离线误差对照，核查回合内无第二次地形观测、无真位姿/真速度进入actor。先对“动起来但无新感知”做接口验证，再训练。
4. 实现独立Isaac Lab + RSL-RL/PPO入口、随机初始化来源记录和同次恢复。奖励分别衡量抬轮净空、登台推进、支撑、姿态恢复、沿线直行、停稳和平顺性；不编写固定起落动作轨迹供模仿，不提供历史策略。
5. 通过短训、更新证据、同次恢复和干净重载的容器工程门槛后，再固定提交安排正式训练。预算尚未设定，本次框架授权没有启动任何训练/评估队列。

## 验收证据

每回合保留初始地形包、估计值与真实值误差、原始动作/执行目标/实测关节、阶段、四轮相对台阶几何、立面/顶面/棱边接触、触地冲击、实际速度/航向/横向误差与结束原因。已标成功的样本也须审查，不能只看奖励和成功率。

同次恢复未来必须校验run身份、任务和源模型指纹、随机初值、优化器/归一化/随机状态；跨实验读取检查点一律拒绝。日志不承诺PhysX接触状态逐位续接。无周期定时器、无goal；新增自主队列执行须按用户后续授权范围推进。

## 当前检查边界

`python3 -m step_demo check`与`python3 -m unittest discover -s tests -v`只在CPU检查配置/接口和合成事件流，不加载Isaac、不使用GPU、不产生模型权重。检查结果不能冒充PhysX、训练、策略成功或sim2sim验收。
