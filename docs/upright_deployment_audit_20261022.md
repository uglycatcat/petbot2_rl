# 第四批实际部署代码审查（2026-10-22）

范围：12个运行副本固定14dca2d；逐一核查HEAD、工作区和运行config，全部干净，A/B各六组，区别为rolling/instant稳定奖励。检查容器内实际Isaac Lab步骤顺序和RSL-RL PPO实现。未修改运行副本、任务实现、容器依赖或模型。11:23附近已有15次评估完成，无失败任务，尚无终局。

## 已确认问题

1. **轮速slew在当前配置下不起限制作用**。moving_task.MovingAction按wheel_slew×dt限变化；当前900×0.06=54rad/s，大于允许轮速[-25,25]的全跨度50。CUDA复现一步-25→25；已完成15次评估实际最大目标跳变49.385rad/s，车架目标最大单步0.36rad。smooth奖励只惩罚重力方向变化率，rate权重0.002且在归一化后的动作上计算，不等价于对实际轮速/车架速度有充分约束。不能声称当前策略已经实现平滑接管。下一版需把动作平滑约束、对应奖励和独立验收明确化；不能简单强降限幅并假设原策略仍能起立。

2. **小范围命令的成功容差允许忽略小指令**。当前原生速度±0.1m/s、yaw±0.3rad/s，而good速度误差阈值0.12/0.3；单看速度条件，静止可以覆盖整个原生速度范围。路径<0.15m和朝向<0.25rad仍约束累积误差，因此不是所有指令都能靠静止通过。CUDA合成状态测试：机器人保持合格后轮支撑且不运动，连续指令0.01m/s、0.01rad/s，12.06秒后路径误差0.12053m、朝向误差0.12060rad，末2秒held全真。这里只证明判据漏洞，不证明某条实测轨迹实际利用了漏洞，也不是物理可达性验证。下一版须单列非零指令跟踪、停滞比例和分档成功率；旧口径保留用于历史对照。

3. **终止与超时重叠未消歧**。MovingEnvCfg的timeout和failure独立计算；Adapter将原timeout直接传给PPO；评估premature=done & ~time_outs。CUDA复现since≥12时同时physical failure=True、timeout=True，真实失败会不计入premature，训练还会按超时bootstrap。实际安装PPO使用当前transition.values做超时补偿，这是上游近似，不应混称为本项目新增错误。已完成15次评估的physical/path failure与非premature交叉检查未发现重叠样本，尚不能量化历史影响。下一版应令真实termination优先于timeout，并在评估中直接保留真实termination标志；重新验收后使用新固定版本，旧结果不悄悄重写。

## 设计风险，不应冒称已定位根因

- **预热动作不由策略执行，样本仍进入PPO**：MovingAction在active前覆盖策略动作，PPO未做active mask，actor/critic归一化也包含预热。正常预热2–4秒、接管12秒，约14%–25%时间策略无控制作用；更长预热可能占比更高。这并不自动使PPO成为错误的off-policy算法：可视为环境忽略该阶段动作，期望策略梯度为零，但有限样本会浪费预算、增加梯度噪声。后续分段设计应评估接管前物理预热与actor优化样本隔离。
- **遥控轨迹与过渡缓变指令不一致**：raw_reference持续积分原始指令，而command会限加速度；奖励和good仍约束raw轨迹。没有明确过渡可行性预算，起立必须兼顾追赶原轨迹，可能增加训练难度。属于设计取舍，需要分段任务验证，不能仅从代码宣布物理不可行。
- **最终“两秒保持”实际要求更长无中断**：held是17个控制样本全部good（样本首尾0.96秒）；末2秒的每步都要求held，因此实际覆盖约最后3秒good。这是既有严格标准，不是本轮新改，文档应说明，不能为提高分数暗改。
- **短程探索/奖励尺度**：gamma=.997^3、lambda=.95^3对应GAE衰减约0.85/步（60ms），长延迟起立信用主要依赖价值估计。首次held一次性奖励30，与稠密保持项不同；没有return归一化/课程。这些为优化候选，不等于数值错误或已证实根因。
- **接管覆盖有限**：当前仅小范围课程，且必须四轮接触和车架接近目标才接管。15次评估实测接管前进速度范围约[-0.0835,0.0902]m/s，不能宣称已覆盖任意行驶速度/车架姿态。
