# upright MuJoCo 交互验证与正式项目准备

2026-10-27 用户确认：先用当前最佳已评估策略制作 WASD/Space 可体验的 MuJoCo 仿真，作为判断训练框架成熟度的依据。程序位于 `rl_project/std_s2s_upright_project`；`std_train_upright_project` 保持空。两者由 repo 和独立 `rlproj/` 分支管理。尚未迁移训练，也不移动或删除 runs；history 加入忽略规则，后续按依赖清单归档。

## 实施与验收

- W/S 前进后退，A/D 左右转，Space 请求起立或前轮落地；释放方向键请求零速。普通控制、起立中、两轮状态均接收遥控，过渡遵循现有平衡优先限幅。
- 使用已完成独立评估的真实策略，保留 58×5 观测、60 ms 外环、20 ms 冻结平衡反馈、2 ms 转向反馈、五阶段状态机、车架位置/后轮速度目标以及物理限幅。头耳维持初始目标。网络导出不等于 sim2sim 通过。
- 源 MJCF/STL/质量/接触参数只读。MuJoCo 电机接口用外部 PD 实现车架位置目标；迁移差异实测报告，不用脚本动作伪装策略成果。
- 部署新增手动起立请求和完整交接后重新接管，物理状态不重置；只有 R 显式复位。原训练随机换令/自动落地由外部操作者输入替代。
- 先对齐观测和控制，再测真实 MuJoCo 闭环、按键与渲染，记录失败、范围和默认权重的来源。没有跨引擎证据前，不判断“只剩调参”。

## 已实现与真实结果

程序与说明位于 [正式 sim2sim 项目](../rl_project/std_s2s_upright_project/README.md)，独立分支 `rlproj/std_s2s_upright_project`；训练占位分支 `rlproj/std_train_upright_project` 保持空树。main 管理清单、索引与忽略规则。

默认选择第十八批续训 r42/model_598（实际累计600更新，检查点SHA `40362f98…`）。其新种子20261137、±0.20 rad、180秒 Isaac 独立评估完整/基本遥控62/64，属于已完成候选中的并列领先；没有宣称唯一最优。导出包含 actor 和冻结平衡网络，CUDA 1024条校验三项最大误差0。源模型指纹保持 `b82c59db…`。

MuJoCo固定诊断：

| 场景 | 结果 |
|---|---|
| 默认车架，18秒混合遥控 | 完整起立/保持/落地/交接，基本遥控通过 |
| 默认车架，180秒混合遥控 | 完整交接；60项响应93.33%通过，10个停车段全通过，最大停车位移21.85 mm |
| 默认车架，键盘上限0.05 m/s / 0.15 rad/s | 18秒混合遥控完整交接，基本遥控通过 |
| 默认车架，持续后退 | 完整交接；覆盖不足不计全类别基本遥控通过 |
| 车架-0.15 rad / +0.15 rad混合遥控 | 前者完整/基本通过，后者落地交接超时 |
| 静止指令与重复起落 | 静止能起立保持但落地交接超时；重复流程第一次完成、第二次起立超时 |

这些是固定开发场景，不是随机初态成功率。r43对照同样有成功和失败，全部摘要保留在项目 `validation/20261027/scenarios.json`；逐步轨迹在 `artifacts/s2s_validation/` 和 `artifacts/s2s_initial_*`。没有把渲染复现当作新增独立样本。

接口验收：9个纯逻辑模块与固定训练源码逐字节一致，4个控制定义去除Isaac依赖后AST一致；35组观测与原函数最大误差0。支撑力均值与源模型重量相符，航向速率独立积分、执行器限幅、键盘事件和GLFW窗口运行检查通过。具体证据见项目验证页。GUI在虚拟显示下已启动/绘制/退出，真实人工体验尚待用户在桌面完成。

## 对框架成熟度的判断

已经具备可复现的训练、导出、包含全部反馈环的 MuJoCo 闭环与诊断工具；默认低速完整流程具有实测成果。尚不能判断为“框架已完善、只需调参”：落地接触/交接、重复接管和不同初态/航向仍存在行为缺口。训练框架可继续复用，正式训练迁移后置，避免把未验证假设固化到标准项目。

重复起立失败可能与起立仍保留世界坐标输入或新的接管状态分布有关，尚未做控制变量归因；跨引擎的接触求解和显式/隐式伺服也有差异。下一步应先依据实际体验确定可接受边界，并针对这些已复现问题做诊断，不继续泛化精度扫描，不改源模型掩盖差异。
