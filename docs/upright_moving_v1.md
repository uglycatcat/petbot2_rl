# upright_rl_demo：运动中接管与遥控首版（2026-10-19）

## 已确认目标

正常四轮触地行驶中随时切入，在当前速度、转向和左右相同车架角度下平滑起立，随后以两后轮支撑继续遥控行驶。不先停车，不包含摔倒恢复。全程接收遥控，过渡期允许受动力学约束的短暂速度调整与跟踪误差；由命令轨迹跟踪替代回原点。源模型及伺服参数不变，头耳维持默认位置。见[需求基线](upright.md)。

## 实现与接口

新增`train_moving.py`、`upright/moving.py`和`upright/moving_task.py`，保留旧`train.py`及第五版固定副本。三路策略输出为共享车架位置、左后轮速度、右后轮速度；仍是位置/速度接口，不改成力矩。41维单帧、5帧历史共205维，包含原始及平滑命令、两套轨迹误差、实际已执行目标和接管阶段。

外部命令接口`set_remote_command(env, [v, yaw_rate], env_ids=None)`使用m/s及rad/s，调用后对应环境停止随机重采样，复位后恢复采样模式；超出配置范围或非有限输入会报错。首版默认请求范围为±0.3m/s、±1rad/s，允许通过参数设置不超过±0.6m/s、±2rad/s；这只是初始工程范围，不是实机上限，更不是已证明覆盖任意速度。车架目标使用源范围[-1,1.2]rad，可通过参数缩小范围。

### 真实行驶初态和交接

每次episode先从源模型默认状态开始，在同一PhysX环境中进行普通四轮行驶准备，车架随机目标、前进/后退/左转/右转/混合命令分组采样。接管时刻在2–4秒随机请求；只有四轮实际接触、两车架均距目标小于0.08rad且持续至少0.12秒才接管，6秒仍不满足则作为准备失败单独统计。没有直接写入随机根速度或拼接不一致的轮速；准备动作不包含起立序列，不是示范训练。

普通行驶用源MJCF实测后轮半径约0.03m、轮距约0.10m的差速关系生成轮速，未修改模型；摩擦/滑移使请求与实际速度不完全相同，评估保存实际接管速度、角速度及车架角度。接管继承已执行位置/轮速目标和连续观测历史，命令过滤器从实测速度/角速度初始化，轨迹原点取接管位置；不会在接管时重置成零动作或清空历史。

准备段也是环境时序的一部分，策略动作在该段被普通行驶控制覆盖、任务奖励为零，阶段在观测中显式给出；PPO仍会采集这部分步数，存在额外样本开销。后续是否改成已采集物理状态库应依据性能，不把准备控制当教师起立策略。

### 命令、平滑与奖励

全程输入线速度/角速度。一般命令变化率限制为0.6m/s²及2rad/s²；起立且支撑不足0.3秒时为0.3m/s²及0.8rad/s²，另限制名义横向加速度约0.4m/s²。执行目标每控制步限制车架变化≤6rad/s、轮速变化≤120rad/s²，控制周期0.06秒；这是目标变化率限制，不能直接证明机身加速度或实际体验已经平滑。

原始命令与过滤命令分别积分参考轨迹；策略同时看到二者，奖励包含实际支撑、有效离地最高进展、过滤命令跟踪、原始命令跟踪、原始轨迹/朝向误差、姿态变化和平滑动作。起立阶段还有有限幅度的原始命令误差惩罚，降低先停住再起立的收益；效果待学习验证，不能保证策略不会临时刹停。

运动成功要求连续1秒仅后轮有效支撑、前轮中心>0.12m、原始速度误差<0.12m/s、原始角速度误差<0.3rad/s、原始轨迹误差<0.15m、朝向误差<0.25rad、头耳误差<0.05rad、横滚重力分量<0.15、重力方向变化率<0.8/s。取消旧任务低线速及固定世界朝向的要求。另报告最后2秒持续达标、低速停滞比例、实际前向加速度峰值、请求/实际速度误差、准备失败和各初态分组覆盖。

## 后续训练方式

先用较小命令范围验证三路策略能学会起立并保持移动，再扩大命令幅度、转向变化和车架范围。现有CLI支持分别控制这些范围；自动成功率课程尚未实现，不能声称已经启用。正式学习前需要按实际接管速度、转向、车架角分桶，保留固定独立评估集并报告每桶覆盖与成功率；当前随机64环境只用于工程验收。

旧第五版检查点仍为静止任务基线，不能直接加载新三路/205维网络。加载检查任务名、动作维数、控制周期、分布参数、代码与源模型指纹；不静默忽略结构差异。是否进行旧网络迁移另行设计，本版从头训练。首批长训的重点是验证“运动不中断地起立”，不是直接声称任意正常行驶状态均已覆盖。
