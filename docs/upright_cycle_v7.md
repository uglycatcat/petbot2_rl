# 完整循环第七版：持续遥控与运动反馈

2026-10-23。GPU工程验收完成，第七批固定版本部署已启动；各组是否进入PPO、评估是否开始以[当前交接](current_handoff.md)所列状态文件和实际进程为准。工程通过不等于任务达标。

## 依据与边界

[第六版长训](upright_cycle_batch6_long_results.md)12组训练及60评估完整结束。2399独立测试交接767/768，但联合跟踪与新版完整合格均0/768；延长预算改善平均误差，没有解决遥控质量。固定类别、约4秒两轮阶段不能代表持续遥控。原普通行驶代理仅发出理想轮速，纯转向接管时实际速度接近0。

[驱动诊断](upright_yaw_diagnostic_20261023.md)发现同一只读模型四轮/两轮均有小差速输入衰减；运行时驱动参数与配置一致，未确认模型或参数写入缺陷。单独PI/前馈干预提高部分平均转向响应，却仍有瞬时振荡和交接退化，不能直接作为已验证控制器部署。因此第七版补反馈、时序与任务覆盖，并比较两个策略输出结构。两组共享其他改动，无法用本批单独归因每项公共改动的收益。

源模型、物理参数、2 ms物理步长、60 ms策略周期不变；仍输出对称车架位置和左右后轮速度，头耳保持默认位置。不加入示范轨迹，不恢复AGILE或废弃旧夜间数据。

## 公共任务改动

- 指令采样/平滑在策略观察前完成，评估断言动作对应的原始指令与该步策略看到的一致。起立和落地允许为平衡调整运动；不追赶起立过程的历史位置欠账。
- 每个环境按前进→停止→后退→左转→右转→曲线循环，初始类别错开，每3–4秒换令；幅度独立采样。两轮遥控保持8–12秒，从进入两轮阶段计时；独立长场景保持30秒。保留显式模式请求和落地锁存。此版本检验确定类别顺序下的混合遥控，尚非任意时序输入的完全验证。
- 在原49维单帧观察后追加8维：瞬时前向/航向速度、位姿差分经120 ms低通的两轴速度、有效指令误差、两轮阶段误差积分。5帧共285维；新增特征按量纲显式缩放。旧两组位置误差观察限幅±0.3 m，归一化接管/阶段计时观察限幅0–1，避免持续遥控时输入随时长无界增长；内部时钟、位置误差与失败判据仍用未限幅真值。原245维actor按每帧映射迁移，新特征权重初始为0；critic/optimizer重新初始化，不能称完整续训。
- 两轮跟踪奖励对每轴采用`1/(1+(error/tolerance)^2)`，合成为`0.25*(sv+sw)+0.5*sv*sw`，避免单轴优秀掩盖另一轴；70%基于滤波运动、30%基于瞬时运动，权重12。有效平滑指令用于奖励；独立验收仍保留原始指令与瞬时速度的严格口径，滤波结果不得冒充严格合格。
- 用户已放宽前轮落地速度要求。触地冲击、下降速度、触地速度惩罚权重分别降为−0.2、−0.3、−0.2；保持前轮落地、身体安全、交接和动作变化约束。新版完整合格离线口径继续排除旧触地速度/力硬门槛；原`qualified`字段保留并单独说明。
- 四轮预热及交接后的内部普通行驶代理使用实测运动闭环。接管必须同时满足四轮触地、对称车架到位及实际速度接近请求；容差为`[0.01 m/s,0.025 rad/s]+0.25*abs(command)`。这样无法用“发出了转向指令”替代“正在转弯”。这仍是内部代理，不等于已接入外部控制器。

## 唯一组间对照

A保留策略直接输出轮速共同量与半差：`common=25*a1, diff=5*a2`。B在两轮阶段渐入转向前馈加策略修正：`diff=1.667*yaw+0.7*tanh(yaw/0.03)+1.5*a2`；共同量和车架仍由策略控制，0.6秒渐入/落地渐出。前馈只是基于诊断的候选工作点偏置，并非已辨识的逆模型；策略必须补偿非线性与稳定性。两组均不使用差速低通，均采用fine探索配置。

计划从第六版长训A42–A47各自2399 actor成对迁移到A/B，避免父策略差异混入对照。原生范围保持v±0.05 m/s、yaw±0.15 rad/s、车架±0.15 rad；较宽范围仍为0.1/0.3/±0.3。先验证低速控制框架，再扩范围。

## 验收与分析要求

发布前必须完成CUDA状态机/迁移检查、容器内PhysX接管与换令检查、两种结构的PPO短训/重载、正式环境数资源实测。失败保留证据、修复后新建固定版本，不能热改运行副本或只用CPU检查替代。

正式评估需区分：实际接管运动、起立、长时两轮平衡、六类覆盖与跨类切换矩阵、前向/转向/联合严格跟踪、前轮落地、交接及新版完整合格。同时分析误差时序，区分换令瞬态、稳态偏差与振荡。任何未起立/预热失败都计入总体分母；不能只在成功起立子集宣称成功率。

周期定时器保持停用；批次完成/异常退出事件续接保持授权。正式训练前检查实际进程，整卡显存78%守护；计算利用率尽量接近80%，不挤占其他用户。

## 工程验收记录

候选任务`1f1357a`，固定副本`runs/cycle7_gate_candidate1`；产物`runs/_cycle7_gate_candidate1`。CUDA契约检查通过：每环境六类覆盖、49→57逐帧actor映射等价、联合奖励性质、实测接管门槛和新保持计时。两种结构各64环境PhysX探针正常退出，均接管64、进入两轮58、落地交接58、失败6、未结束0，原严格合格0。共同的6例在两轮干预前失败，不能从总体分母剔除。

两组64例接管实测均在新容差内；21例纯转向初态的请求/实测绝对转向速度均值为0.09093/0.08225 rad/s。进入两轮的episode实际发生跨类切换，合计181次/组；正常保持段最长12秒。该结果验证新任务覆盖与执行链路，不是学习后新策略效果；后续短训与重载记录见下文。

首候选两组2048×40短训均正常退出、所有标量有限，单任务约9.25/9.30秒每iteration、增量显存约3415 MiB。4096×8资源探针正常退出，增量显存4197 MiB、约12秒每iteration。4096单任务样本吞吐更高，但四个这样的训练会挤掉独立评估的4000 MiB保留空间；本批保留统一2048环境和6对种子，避免把组间控制差异与采样预算混在一起，并允许评估与训练交错进行。计算利用率须在实际并发后采样，不能据显存占用声称已达到80%。

首候选40更新后的30秒重载评估均正常执行，但A/B只起立57/55，全部64在落地前失败，完整交接0。两轮失败平均发生在进入阶段后约21.1/23.0秒，不是队列/加载错误；当时没有足够姿态字段精确区分物理失败原因，不能臆断根因。此结果不作为长时能力通过。复核发现计时及位置观察会持续增大，候选`54c2623`限制这些观察并新增失败原因位图、投影重力与基座速度轨迹；必须复测后再发布，首候选记录完整保留。

失败位图位值为：1非有限状态、2机身过低、4倒置/后翻姿态、8线速度过大、16角速度过大、32预热未满足接管、64起立超时、128落地超时、256离起立位置超过3 m。同一步可有多个原因；评估断言位图非零与原failure判据严格一致，不改变终止门槛。

候选`54c2623`的两组2048×20短训正常退出、全部标量有限，单任务约9.09/9.14秒每iteration，采样增量显存3479 MiB。重载均接管64/64、未结束0；原生8–12秒交接A/B为56/58，30秒交接为8/27，严格合格均0。30秒A失败原因：起立超时7、后翻2、3米范围超限37、落地超时10；B分别5、1、23、8。出现真实长时遥控和落地轨迹，但持续速度偏差仍明显。与首候选使用不同短训预算，不能把差值单独归因观察限幅。工程gate保存在`runs/_cycle7_gate_candidate2/release_gate.json`，所有失败轨迹保留。
