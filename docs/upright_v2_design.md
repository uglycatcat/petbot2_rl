# upright_rl_demo 第二版设计（2026-10-16）

状态：完成原示例实测、首版日志分析与设计；第二版代码已实现，已完成GPU短训与重载，工程检查通过但学习效果未通过，最新部署见[训练记录](upright_v2_training.md)。项目正式名称不变，独立于 recovery_agile_01。

## 用户确认的任务

从默认构型、零速度初始化，策略使前轮离地，保持仅两后轮支撑且稳定。过程中允许离开起点，完成后必须回到初始水平位置；不能持续乱跑，也不是全过程禁止位移。左右车架共享**位置目标**，左右后轮共享**速度目标**；头、耳维持初始位置目标。策略仍为两路输出，不能改成力矩策略。jump_demo的力矩控制只用于实现示例，不能据此更换训练动作接口。示例不作为模仿数据、参考轨迹或训练初始化库。

“原位置”实施建议：复位后记录base_link的世界水平坐标p0，后续使用相对误差p−p0；完成容差暂拟5 cm，终局持续1秒。该容差及以下数值是待物理验收的工程参数，不是用户指定精度。参考点固定，不能在切换到后轮支撑时重新定义起点。

## 两阶段奖励，一套策略

采用单个有历史观测的策略，奖励和事件按实际接触状态分段，不给固定时间动作表。

|阶段|需要学会的行为|奖励与切换|
|---|---|---|
|抬升|车架与轮子协调使前轮真正离地；允许必要平移及角速度|以前轮实际净空进展和后轮有效支撑为反馈。机身抬头、前轮仍接地不算阶段完成。暂不施加强低速/回位惩罚，只限制过大偏移与危险状态。前轮净空和后轮支撑连续确认约0.1秒后转入第二阶段；首次转换给一次奖励。|
|平衡并回位|维持后轮支撑，向p0移动并在p0附近稳定|持续奖励有效支撑、姿态稳定和回位进展；位置误差越小，目标平移速度逐渐趋近0。远处静止不应比受控回位得分高。回位后连续稳定1秒，才给完整任务成功奖励。|

第二阶段包含回位和停稳，不另立独立策略。失去有效后轮支撑超过确认窗口则退回抬升阶段，重置连续保持计时；重复起落不能重复获取首次切换奖励。瞬时碰撞抖动需去抖，但超过容忍时长的接触丢失必须记失败，不能被平滑隐藏。

不强制模仿示例的先前进0.4m、车架+1.2→−0.4或具体俯仰角；这些用于理解动力学及物理检查，不是训练轨迹约束。

### 奖励实施原则

- 抬升进展使用有符号势差，并配合有上限的阶段内反馈。实施时两次仅势差短训阶段2全零，故增加准备/离地持续奖励（抬头部分至多0.5/s，阶段1合计至多2/s），阶段2实际后轮支撑2/s并额外奖励回位、稳定；不把局部抬头当完整成功。跨阶段边界/复位的势差明确处理。失败终止不能返还负势差，阶段来回切换不能刷分。
- 第二阶段的平移速度参考可用 `v_ref=clip(−k*(p−p0), v_max)`，暂拟k=1/s、v_max=0.2m/s；它只定义奖励目标，不替代策略发动作。离家远时要求轮速为0会妨碍回位，故不全程惩罚轮速本身。
- 平衡评分用姿态/关节角窗口波动、机体速度以及后轮支撑；与回位质量联合计分，避免远处支撑获得完整奖励。可用质心相对后轮支撑线偏差作低权重诊断/塑形，不能将固定pitch或固定车架角当作唯一平衡姿态。
- 成功奖励优先于“只抬起”“远处站住”；先在记录轨迹和负控制上核算折扣累计回报，再定各项权重。连续项乘dt、一次事件项只计一次，避免频率与回合长度改变奖励意义。
- 平顺性与能耗保持小权重，任务成功稳定后再逐步加强；不能在抬升时惩罚所有有效加速，也不能用零动作换取高额静止奖励。
- 回报/优势归一化应独立核对概率契约；不加入recovery的终态极低方差门控。不为保住“站住”把探索直接归零。

## 成功、边界和观测

以下为首轮实施起点，须在MuJoCo及PhysX分别校准，不能为让RL数字变好而事后换标准。

- 支撑：两个后轮有效接地；前轮和其他部位无持续支撑。前轮中心>0.12m作为几何辅助，不用机身高度代替真实离地。接触力窗口约40–100ms，去抖与瞬时值同时记录。
- 稳定：连续1秒内pitch/roll摆幅暂拟<0.05rad、车架角摆幅<0.03rad；平移速度<0.10m/s，配合短窗角速度诊断。原始速度峰值仍保留异常保护，但不以每个2ms样本都小于0.4rad/s作为平衡的唯一条件。位姿窗口采用原始样本，防止滤波掩盖大幅振荡。
- 回位：该1秒内base_link水平误差始终≤0.05m；头/耳目标固定，实际角偏差也须检查。建议实际偏差<0.05rad，超出则报告失败，不只检查命令相等。
- 过程边界：暂拟最大水平偏移0.6m（原示例峰值0.405m），越界、非有限状态或持续跌倒结束回合。0.6m是容许过程范围，不是终局位置容差。另记录路程，防止在范围内反复绕行。
- 不只记录“回合曾成功”：同时记录完整任务首次达标、最后1秒达标、首次离地时间、最长支撑、回位误差、最大偏移、实际头耳偏差与各失败条件。评估完成后继续保持2秒，检查是否随后跌落/离开起点。
- 观测保留5帧历史，增加阶段、相对起点误差、阶段/回合时间和保持计时。接触与几何可先供critic和奖励使用；actor若加入接触状态必须明确部署可得性。观测不得用会随阶段重置的起点或隐藏计时状态。

## 训练和验收设计（实际执行状态见训练记录）

1. 先完成阶段/窗口诊断和控制接口验证。动作仍为车架位置及轮速，伺服和力矩上限不绕过、不改源物理。检查限位、位置跟踪、响应时序及末态稳定；不能以示例用了力矩为由改动作类型。
2. 用真实示例作“抬升+平衡”正控制、“完整回位”负控制；默认不动作完整任务负控制。用掉轮、身体支撑、远处站住、反复起落、掠过起点等案例验证检测器。构造静态后轮平衡且回到p0的状态，只能验证判据，不能冒充策略可达性的正控制。
3. 实现后先容器内PhysX、128×100短训及重载门槛，检查数值、阶段反馈与重载。实际短训仅抬升准备反馈非零，阶段2仍为零；另以位置/速度物理诊断确认阶段可达。工程运行通过与学习效果通过分开记录，正式批次仍是探索效果实验，不能称为已通过学习效果验收。
4. 正式候选从头训练两组种子，2048环境×3000 iteration，固定提交。12秒回合为起点（抬升实测约2.5秒，余下时间用于回位与稳定），50Hz控制；两路有界分布及5帧历史保持。学习率最初拟固定2e−4；短训反馈偏弱后，实际候选固定6e−4，gamma暂拟0.997以覆盖较长的回位收益；旧0.99在8秒后的折扣仅约0.018，不能仅靠远期成功奖指导起始动作。这些超参数待短训验收，不宣称已验证最优。
5. 首轮不同时叠加教师学生、额外参考轨迹或大规模随机化。全部正式起始状态仍为默认构型零速度；阶段奖励不是将训练改成从半起立姿态开始。完成后才增加小扰动泛化对照。
6. 250/750/1500/2999固定检查点评估，保存完整单轨迹与关键帧，不再只留最高高度。默认起点确定性复测不虚报场景覆盖率。中途若只有抬升奖励增长而阶段2/回位无进展，先查看轨迹，不盲目加长。
7. 若发起训练，延续专用容器及GPU0/1总显存<80%的限制；启动前查进程并固定版本。recovery_agile_01独立推进，不改其已有运行副本。实际执行状态见[训练记录](upright_v2_training.md)，不从设计计划推断已启动。
