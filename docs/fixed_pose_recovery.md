### 恢复思路与实机经验的边界（2026-10-14 用户补充）

用户确认：实机上使用更全面的程序，按这一思路可成功恢复其测试过的所有场景；实机程序、测试分布与逐次结果尚未归档。当前 MuJoCo 程序仅是简化演示，不是实机版本，缺少部分动作转换和细化处理，其覆盖率不能代表完整方案的能力。

核心过程是利用左右车架这两个大关节改变支撑和身体朝向，使机器人进入后倒、两个高摩擦后轮能够触地的状态，再由后轮带动机身运动，通过急停/制动促成翻身，最终收回默认构型。对 pitch > 0 的状态，先设法转入 pitch < 0 的后倒状态；重点是建立有效后轮接触及后续动态翻转，不要求各关节始终朝默认角单调靠近，也不要求机体始终越来越直立。pitch 符号是当前演示的分支代理，不能单独证明后轮已有效触地。

代码现状：只在请求 STAND UP 时选分支，之后按固定时间执行；负 pitch 段后轮依次给 +5、−7 rad/s 目标，包含反向速度指令，而非仅设零速。它未按实际接触、速度或翻转进展闭环切换阶段。上述物理思路来自用户实机经验，代码行为来自静态阅读，本次未在服务器重跑仿真。

动作组按点击 STAND UP 时的状态选择，界面不标出是哪一套：

| 条件 | 时长 | 动作 |
|---|---|---|
| 未摔倒 | 1 s | 五个位置关节回到模型初始角，后轮速度回到 0 |
| 摔倒且 pitch < 0 | 4 s | 下方「负 pitch」 |
| 摔倒且 pitch ≥ 0 | 8 s | 下方「正 pitch」前 4 秒，再接上整套「负 pitch」 |

摔倒且 pitch 正好为 0 走 8 秒那套。未摔倒时不看 pitch 的符号。

这套动作用来看构型、接触和恢复过程需要哪些姿态。它不是模仿学习的示范轨迹，也不代替策略评估。源 MJCF 仍是五个力矩执行器加两个速度执行器；本程序在力矩执行器上做外部 PD，后轮使用模型里的速度执行器。

## 固定姿态恢复

启动后停在 RECOVER，默认站姿会被保持。PASSIVE、TRACK、RECOVER 三者互斥。STAND UP 接管其中任意一个，结束后回到进入前的模式；若进入前是 TRACK，三条 bar 的目标一并恢复。只有 TRACK、且不在恢复动作中时，才能拖 bar。

```bash
python robot_controller_demo/pose_recover_demo/main.py
python -m unittest discover -s robot_controller_demo/pose_recover_demo -q
```

图形程序需要本机显示器和已安装 MuJoCo 的 Python。单元测试检查各时间点的关节是否靠近指令，不打开窗口，也不是摔倒成功率。

### 模式与界面

- **PASSIVE**：全部执行器出力为 0。后轮速度伺服在 `ctrl = 0` 时仍会刹车，所以同时清掉速度执行器的增益和速度偏置。
- **RECOVER**：头、双耳、左右车架在 2 秒内平滑回到模型初始角，后轮速度目标为 0。不管机体在空间中的朝向，不写浮动基座。左右前轮没有执行器。
- **TRACK**：三条 bar 分别给出左右车架、左右耳、两个后轮的同一带符号目标。头保持进入 TRACK 时的角度。车架范围 -1.0～1.2 rad，耳朵 -1.0～3.0 rad，后轮 -25～25 rad/s，与模型一致。

界面为英文。右侧是 `lower_body` 上 IMU 站点的三轴姿态（红 X、绿 Y、蓝 Z；灰轴为世界系），以及 roll / pitch / yaw。IMU 与机体系重合：+X 前、+Y 左、+Z 上。欧拉角为内禀 ZYX。在 MuJoCo 窗口中双击机体后 Ctrl 拖拽，可改变空间姿态，姿态显示跟着变。

### 摔倒与 pitch

摔倒看 IMU +Z 与世界 +Z 的夹角。达到 45° 标为 FALLEN，回到 35° 以下才清除。单纯偏航不算摔倒。

pitch 是上述欧拉角的俯仰分量。分支用的是按下 STAND UP 那一刻的 pitch，不是被动沉降统计里的俯仰分布。

### 负 pitch（摔倒且 pitch < 0，共 4 s）

脖子即 `head` 关节。第 1 秒之后它保持模型初始角。左右同名关节使用同一带符号目标。段内用 smoothstep，端点速度为 0。

| 时间 | 耳朵 | 车架 | 后轮速度 | 脖子 |
|---|---|---|---|---|
| 0–1 s | 回到初始角 | 回到初始角 | 0 | 回到初始角 |
| 1–2 s | 1 rad | 1.2 rad | 0 | 初始角 |
| 2–3 s | 0.3 rad | 保持 1.2 rad | 0 | 初始角 |
| 3–3.5 s | 保持 0.3 rad | 保持 1.2 rad | +5 rad/s | 初始角 |
| 3.5–4 s | 保持 0.3 rad | 保持 1.2 rad | -7 rad/s | 初始角 |

第 1 秒的起点是按下按键时的关节角。

### 正 pitch（摔倒且 pitch ≥ 0，共 8 s）

前 4 秒里，第 1 秒之后脖子、耳朵保持初始角，后轮速度保持 0。第 4 秒结束时左右车架在 -0.4 rad，随后整套负 pitch 动作接上；其中开头那 1 秒把车架从 -0.4 rad 收回初始角。

| 时间 | 动作 |
|---|---|
| 0–1 s | 五个位置关节回到初始角，后轮速度回到 0 |
| 1–2 s | 左右车架到 -1 rad |
| 2–3 s | 左车架到 1 rad，右车架停在 -1 rad |
| 3–4 s | 左右车架到 -0.4 rad |
| 4–8 s | 上表的负 pitch 动作。4–5 s 从车架 -0.4 rad 回到初始角，再进入耳朵、车架和轮速 |

### 执行

位置关节外部 PD，增益按头、左耳、右耳、左车架、右车架为 KP `[8, 4, 4, 12, 12]`、KD `[0.35, 0.04, 0.04, 0.35, 0.35]`，力矩裁到各执行器的 `ctrlrange`。运行时把积分器设为 `mjINT_IMPLICITFAST`，不改 MJCF。

## 被动沉降

`collect_resting_poses.py` 关闭全部执行器，只留重力、关节阻尼、摩擦和接触。位置关节从 0 释放，初速度为 0，最低点离地 1 cm。无窗口。

样本：种子 0。均匀朝向 900 套，四元数在 SO(3) 上均匀抽取；超时后再补抽。另有五类定向探针各 20 套：左侧躺、右侧躺、倒立、头朝下、头朝上，每套再绕世界竖直轴转一个偏航角。停稳条件为 0.5 s 内陀螺绝对值不超过 0.05、加速度变化幅度不超过 0.25，且加速度模长接近重力、身体与地面有接触。单套最长仿真 12 s。超时不计入这一千套。仍接近站立的样本保留。MuJoCo 3.9.0。

```bash
python robot_controller_demo/test/fall_pose_statistics/collect_resting_poses.py
```

原始记录、超时样本和汇总在 `robot_controller_demo/test/fall_pose_statistics/output/`。倾斜角是身体 +Z 与世界 +Z 的夹角：0° 站立，90° 放平，180° 倒立。

**实测（1000 套停稳，55 套超时，0 套非有限）：**

- 倾斜角最小 6.3°，p50 113.7°，p95 116.8°，最大 **121.7°**。130° 以上为 0。
- 主簇在 110°–120°，584 套。其次 50°–60° 有 163 套，90°–100° 有 99 套。0°–20° 共 8 套。
- 全部停稳样本的 pitch：最小 -84.5°，p50 -57.3°，最大 76.0°。正负两侧都有。
- 定向探针各 20 套全部停稳。终态倾斜中位数：左侧躺 113.7°，右侧躺 113.8°，倒立 116.6°，头朝下 89.4°，头朝上 98.0°。左侧躺、右侧躺和倒立都离开了放入时的朝向。

采集脚本用相对仓库根的路径加载场景。`summary.json` 的 `meta.scene` 记为 `robot_description/mjcf/scene.xml`。

采样边界：这 1000 套是给定采集条件下的被动停稳参考，不是全部可能倒地状态的穷举，也不是恢复成功率测试。位置关节从零位释放、贴地 1 cm 放下，与训练中关节随机化、较高处落下的初态生成不同；不能将本批最大倾角或各簇占比直接当作所有场景的硬边界。
