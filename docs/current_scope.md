# PetBot 自恢复：当前需求基线

更新日期：2026-10-13。本文只记录**已确认的需求与选型**，不记录进度、不提供安装配置。进度见 [AGENTS.md 的进度报告](../AGENTS.md#进度报告文档主线)。

## 项目边界

本仓库是一个独立的 Git 仓库，可在任意位置检出，程序不依赖宿主机的绝对路径。

- **训练全部在训练服务器上进行**；桌面机不承担训练，只在最后用 MuJoCo 等检验训练效果（两台设备的判断方法见 [AGENTS.md](../AGENTS.md)）。
- PetBot 实验项目放在 `demo_project/` 独立 checkout，首个为 `recovery_agile_01`；由根 repo 清单管理，代码在 `demoproj/recovery_agile_01` 分支版本化，见[管理约定](engineering_handoff.md#版本管理与双端协作)。
- 参考项目与其产物放在 `reference_project/` 下，**不进版本管理**；项目文档、配置与 PetBot 自有代码正常提交。
- 旧共享环境、旧容器与旧 Python 管理方式不再适用。

## 目标与验收

### 已有能力与强化学习的目的

PetBot 的轮足结构在默认构型下即可静稳定站立，无需单独训练一套站立策略。用户已验证，机器人可从任意摔倒姿势，通过几个固定姿态之间的转换恢复站立。这是项目已有的恢复可行性基础；测试分布、逐次结果与动作序列尚未归档，不等同于 RL 策略已通过全姿态评估。

引入强化学习的目的是在已有恢复能力基础上，学习**更自然、连贯、平滑的恢复动作**，同时保持恢复成功率与终态稳定性。“自然”是动作质量目标，具体评价指标和阈值尚待确定，不能仅以是否站起来作为完整验收依据。

训练必须支持**位置目标与速度目标的混合输出**，具体为下文规定的 5 路关节位置与 2 路后轮速度。项目**没有预先准备的参考动作流或示范轨迹数据集**，训练应通过与仿真环境交互和任务奖励学习恢复行为，不依赖已有动作数据的模仿学习。已验证的固定姿态转换说明恢复可行，不应被默认视为可用的训练示范，也不要求策略复现该转换顺序。

### 恢复范围与验收

在训练服务器上训练完整翻倒自恢复策略，再将同一策略迁移到 MuJoCo 做闭环验证。场景为平地上被推倒、坠落后的侧躺、仰躺、趴倒等状态。所有当前模型允许的身体接触均可利用，头部、耳朵可以支撑地面。

目标是恢复默认站立构型并持续稳定，同时验证未见翻倒状态下的成功率、耗时、平滑性和失败类型。水平位置与航向暂作为自由量，具体成功阈值与测试分布在环境设计时确定。

## 与参考项目的本质区别

**PetBot 本来就能轻松站住**：默认站姿是四轮着地的静稳定姿态，站立这件事不需要策略去"学会"。

而 `recovery` 这类轮足翻倒起身项目，研究对象默认**连"站住"都还没解决** —— 它们的站立姿态是要学出来的，所以才有基座高度 / 姿态塑形、ED-CW 类课程，以及"站住了但还在晃"这种失败模式。

**影响**：参考项目的奖励权重、课程与成功判据**不能直接照搬**。PetBot 的恢复目标是"从倒地回到本来就能站住的默认构型"，参考项目里为"学会站立"付出的那部分（塑形、课程、辅助力）是否需要，要单独判断。

## 动作与执行器

策略输出 7 维连续动作，经各通道独立缩放和限幅形成：

| 通道 | 控制对象 | 目标 |
|---|---|---|
| 5 路位置 | 头部、左耳、右耳、左轮架、右轮架 | 关节角度，rad |
| 2 路速度 | 左后轮、右后轮 | 角速度，rad/s |

该表为逻辑分组，最终索引顺序需在训练与推理配置中一致定义。前轮无动作通道，保持被动。

Isaac Lab 计划采用位置/速度 action term 与 `ImplicitActuatorCfg`，由仿真内部闭环执行。MuJoCo 对应原生位置/速度伺服。闭环仍具有有限增益、力矩上限和动力学约束；本阶段不做真实 PWM、电机辨识或 sim2real 标定。

**当前实现状态**：源 MJCF 仍为五个力矩执行器加两个速度执行器。首个 demo 已实现派生 MJCF 的原生位置伺服和 Isaac Lab 隐式混合伺服配置；CPU 模型一致性检查通过，PhysX 控制响应未验证。早期键盘 demo 用外部位置 PID 驱动那五个力矩执行器，该 demo 已废弃、与后续 RL 无关。

## 技术路线

- 平台：训练服务器上的 Isaac Lab + RSL-RL + PPO。
- 论文型参考：`recovery`（轮足倒地起身，**已试训并收官**：三代 15+ 实验未达论文判据、卡点"站定"，2026-10-13 关闭本条线，见 [试训汇总](reference_recovery_validation.md)）。
- 训练工程参考：`robot_lab` 的 Go2W 混合动作与执行器配置。
- 恢复任务参考：`WBC-AGILE` 的倒地状态采集、辅助探索、奖励与课程。
- 方法补充：`getup_gym` 的轮足恢复、`HumanUP` 的动作发现与平滑优化。
- 单元对照：`tron2_rl_lab`、`b2w-rl`、`Wheel-Legged-Lab`。
- 验证环境：本仓库的 MuJoCo 模型（在桌面机上使用）。

框架支持混合动作不等于已经学会 PetBot 的完整翻倒恢复。训练底座复用训练循环、日志、检查点和导出；恢复状态分布、奖励、终止条件及模型接触仍需按 PetBot 设计。

克隆版本是调研快照，不是已验证的 PetBot 训练依赖锁。实际运行哪个参考项目，就在该项目的容器内验证并记录版本。自有训练代码、模型与实施记录统一保存在本仓库中。

## 首个 demo 的已确认范围（2026-10-13）

以当前 repo 清单锁定的 AGILE 为训练与恢复任务底座，借鉴 robot_lab 的混合动作配置；与服务器参考试训并行推进，无需等待参考试训结束。项目名 `recovery_agile_01`。

首版从全方向随机姿态开始：根朝向在 SO(3) 上均匀采样，有界关节在允许范围随机，通过自由落下与沉降形成物理有效初态，随后才交给策略恢复。随机生成分布与沉降后的分布应区分；不要求最终倒地姿态均匀。倒地库只提供初态，不是示范轨迹；独立评估使用另一批初态。首版不要求空中控制或带显著残余速度的动态恢复。

首版验收为训练任务可启动、保存/恢复检查点、TensorBoard 可查看奖励与恢复/稳定性指标；视频、导出及 sim2sim 后置，不取消长期验证目标。源模型只读，通过独立适配层配置混合伺服。成功定义为恢复默认姿态与构型、四轮稳定支撑、身体及轮速足够小并持续保持，水平位置/航向自由；具体容差由实现与试验确定。

## 下一阶段的实现边界

实现要点和阶段验收见 [工程实施说明](engineering_handoff.md)。

1. 机器人资产转换与检查：几何、关节轴、被动前轮、质量惯量和接触。
2. 7 维混合动作与仿真内部伺服。
3. 倒地初始化、观测、恢复奖励、课程、成功判据及评估集。
4. 基线训练与策略导出。
5. MuJoCo 推理适配及 sim2sim 验证。

PetBot 首个 demo 的训练任务代码已实现，并在服务器容器内跑通资产转换、PhysX 导入、pre-learn 与训练/评估链路；首轮 11 组扫描（2048 envs × 3000 iteration）加确定性独立评估已完成，**结论是尚未学出恢复能力**（最好 5 组与开环"保持默认构型"地板基线持平），仍未建立策略导出与 MuJoCo 策略推理闭环。设计与现象见[首版扫描记录](../demo_project/recovery_agile_01/PETBOT_SWEEP_01.md)。

## 已定与待定的区别

平台主线、7 维目标动作、内部伺服、允许全身接触和 MuJoCo 验证是已确认要求。具体 action 顺序与范围、伺服增益、策略频率、观测维度、网络结构、奖励权重、课程、成功阈值及最终依赖版本仍是待验证的工程选择。不得把候选值当作已训练或已验收的配置。

原先关于直接力矩策略、在桌面机训练、共享旧开发容器及 Python 隔离的建议不再作为当前实施依据。
