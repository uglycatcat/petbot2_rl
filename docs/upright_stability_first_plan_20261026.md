# 两轮遥控改为稳定优先：需求与实施建议（2026-10-26）

## 已确认需求与执行状态

用户明确：两轮运动过程中不跌倒是最高优先级；跟踪精度要求低于此前的瞬时联合门槛，允许降低两轮行驶速度和转向角速度上限以维持稳定。具体数值由工程验证确定，不要求用户量化。前进、后退、左右转、停车的基本遥控能力仍需保留；不能以永久静止或忽略指令换取“不倒”。

四轮运动接管、车架位置/轮速输出、同一策略两轮遥控、按请求前轮落地与交接的契约不变。不要求接管前停车，允许起立时为平衡调整速度；两轮速度上限与接管初始运动范围需要分别验证，不能混为同一范围。

**用户已明确授权修改代码、GPU验收、训练部署与今晚自动迭代。第十六批宽容差奖励未单独改善长时稳定；第十七批分阶段局部坐标已改善180秒独立稳定性，新增PPO无一致功能收益，后续交接与起立缺陷按阶段核查，实际执行及最新证据统一见[当前交接](current_handoff.md)。完成/异常事件续接恢复，周期定时器与goal均不启用。** 历史固定副本与结果不变。

## 代码改动建议

### 1. 先重建功能验收，保留历史严格分数

实现选择：`upright/functional.py`分析评估轨迹，由`train_cycle.py`写入独立`functional`报告，`tools/evaluate_cycle.py`编排与收集；不覆盖旧`qualified`结果。

必要条件包括完整流程、要求两轮期间持续保持支撑、无失控/明显持续反向移动、停车能收住、前轮按模式请求落地。未经请求的持续前轮落下或支撑丧失单独记录，不能因最终交接成功就忽略。瞬时严格跟踪降为诊断；基础遥控按实际位移/航向、响应延迟、短窗平均运动和停车漂移评价，允许有限偏差。

稳定、基本功能、范围和动作质量分开报告。宽容差内不继续追逐微小精度，持续非零指令仍须产生对应方向的运动，停车须有独立约束。不能仅把旧容差乘一个系数就认定任务达标。零故障测试只说明在列出的场景、时长和样本中没有观察到故障，不承诺任意场景绝不跌倒。

### 2. 奖励转向稳定与粗跟踪，不重训整个流程

`upright/continuous.py`与`continuous_task.py`：新增显式稳定优先目标；从现有位姿差分平滑运动反馈开始，取消围绕旧瞬时容差陡坡的主要优化压力。采用宽容差饱和的基本跟踪奖励，满足方向与合理运动幅度后不再奖励无意义的精度竞争，瞬时误差留作诊断。不能给小非零命令下的完全不动作同等满分。

第十五批跟踪权重12、平衡权重4，且使用`instant_tolerance`目标。首个工程候选可将跟踪权重12→4，保留平衡及失败项，结合分项累计回报与不动策略反例检查后再决定是否加强稳定项；这是待测初值，不是已验证的最优值。奖励权重比例不能保证安全，分项时长和终止收益也要核对。

从现有候选检查点选择稳定性和基本遥控较好的父策略，保留已学起立/落地；不因旧严格分数为0而从头训练或直接大改网络。主actor冻结时，两轮修正无法修好已冻结的起立超时，需要单独记录并按阶段定位；不把这个缺陷隐入两轮优化结论。

### 3. 把两轮失稳及时识别出来

`upright/cycle.py`与`continuous.py`：区分真正翻倒、持续支撑丧失、未经请求前轮落下、失控移动和阶段超时；用持续时间与接触/姿态联合条件避免单帧接触抖动误判。保持起立和有意落地的阶段语义。训练中的明显不可恢复失败及时终止；预警区间仍允许策略修正，不能用严格姿态静止要求替代稳定。

当前严重物理异常阈值、超时与距起点3 m限制不足以表达上述需求。长时行驶也不能直接把正常累计位移超过3 m当作失稳：必须区分场地边界、允许的持续运动和真正失控/停车漂移；场地保护不直接删除。

### 4. 需要时限制驾驶指令，保留平衡纠偏能力

`upright/moving.py`中的原始指令与执行指令已有分离、加速度限制和速度×转向限制。先复用这些机制，分别标定直行、原地转向、曲线的稳定工作范围；不同时扩大速度、角速度和车架初态，也不为高成功率任意缩到近零。

若固定范围仍有风险，再增加由姿态、角速度与支撑状态触发的平滑限幅，含滞回与逐步恢复，保留原始/限幅后/执行指令及介入时长。限幅对驾驶请求生效，**不直接压低左右轮最终控制输出或突然置零**，避免截断维持平衡所需的短时加减速。接管继续继承实际速度；起立后不补追被限幅期间的虚拟位置债务。

训练可相对允许的执行指令给跟踪奖励，同时报告原始意图的方向响应、限幅幅度与比例，避免“永远把指令变成零”的漏洞。状态限幅不是已经证明有效的安全控制器，需要单独复现与对照，不能和多个网络改动一起部署。

## 实施顺序与停止条件

1. 按新需求重评现有候选；既有独立集若用于调设计，后续验收另用预先固定的新种子与命令序列。先辨认少数真实失稳和停车异常，不默认所有策略都需重新训练。
2. 验收实现和失稳识别先过相应容器GPU工程门槛，再短测现有策略；包括长时遥控、前后反转、左右反转、连续曲线和运动后停车。建议先做每回合2–5分钟，属于待执行的测试长度；必须同时处理场地边界与时限，不能简单延长旧30秒配置。
3. 若现有策略已满足基本需求，优先进入MuJoCo验证；否则只针对真实失败作短期微调。先做基线与一个有明确假设的候选，不再默认每批六对、12组长训。需要多卡时用于独立种子、边界场景和更长评估；资源目标服从实验价值及78%显存守护，不增加无意义副本。
4. 选型优先按稳定失败、基本功能缺失、已验证可用范围排序，再看动作质量与平均误差。达到基本可用性后，不因旧瞬时联合仍低而继续同类精度批次。完整任务仍需独立评估与后续sim2sim验证。

以上方案已获实施授权；具体工作范围、数值判据与最终策略需实测验证。[当前交接](current_handoff.md)记录实施和运行状态，[需求基线](current_scope.md)记录用户已经确认的优先级。

## 运动范围扩展讨论（2026-10-27）

用户体验后的明确反馈：当前0.05 m/s和0.15 rad/s离期望峰值过远，这是最不满意的部分。允许为稳定适度降速不意味着该范围成为最终目标。以下为工程建议，尚未实现或部署；具体峰值未确定，不承诺达到电机理论极限。用户随后明确：继续在`demo_project/upright_rl_demo`迭代，直到用户亲自确认sim2sim可以通过再讨论正式迁移；正式训练目录保持空，当前先讨论、不立即实施。

### 已核查的限制

- 命令采样、`MovingProgress.set_command`及演示键盘上限使用相同的低速范围，当前四轮暖机与两轮遥控也共用该范围；第十八批不是“已经学会高速但UI锁住”。后续应分别配置四轮接管初态/命令范围与两轮安全工作范围。普通四轮`driver_demo`配置为0.35 m/s、1.5 rad/s，当前两轮范围分别为其约14.3%和10%；该比较是软件配置对比，不是实机峰值测量。
- 源后轮速度目标范围仍为±25 rad/s，参考轮半径0.03 m对应无滑动轮缘速度0.75 m/s。这只是运动学参考量，非已验证的车体持续速度；高速仍要给平衡修正保留转速、力矩余量，不改源模型。
- 第十八批`RiseAdapterModel`冻结既有actor、两轮/转向修正、统计及内部反馈，只新增起立头。原样续训不会让两轮控制学习高速。
- 稳定两轮阶段`FastYawFeedback`/`YawFeedback`把目标半差速裁到±2 rad/s（这是轮速单位，不是车体角速度）。按0.03 m半径、0.10 m轮距的无滑动差速近似，持续车体转向约对应1.2 rad/s；实际需测接触/滑移和饱和。不能在此限制不变时要求任意大的车体转向。
- 还有低速设计的观测缩放/冻结统计、小幅有界修正、20 ms冻结反馈、指令加减速与速度×转向限幅。高速要同时审核这些条件；不能仅提高`speed_limit/yaw_limit`后宣称任务设计已适配。
- 稳定监视不是固定0.20 m/s封顶，而是`max(|有效速度命令|+0.15,0.20)`的持续超速判据。停车验收目前在固定0.6秒等待后测3cm漂移；扩大速度时必须区分合理制动距离与停稳后漂移，不能直接删除停车要求，也不能不检查地沿用固定时间。

### 建议训练顺序

1. **先固定策略测当前能力边界**：直线前后、低速左右转分别逐级增大输入，记录实际运动、后轮支撑、共同轮速/差速/力矩饱和和刹停；不同时放大车架范围，不把未训练范围测试当作通过。由结果区分控制器限幅、学习分布不足、接触/执行器响应。
2. **让两轮控制重新参与学习**：从现有权重开始，先保留起立/落地基线，训练足够覆盖加速、保持、制动和转向切换的两轮阶段；核查残差幅度和冻结快环是否限制控制能力，需要时逐步解冻或调整结构，不永久叠加小修正头。保留低速完整循环回归样本，防止扩速后遗忘。
3. **独立推进线速度与角速度课程**：候选台阶为线速度0.05→0.10→0.20→0.30 m/s，角速度0.15→0.30→0.60→1.0 rad/s。不是同步把两个最大值组合训练，也不是保证这些数值都可行；先测稳定基本功能，再升级。通过当前阶段后继续扩展，不能把0.30/1.0当作预先确定的最终上限。达到门槛再扩命令范围可参考[legged_gym原始实现](https://github.com/leggedrobotics/legged_gym/blob/master/legged_gym/envs/base/legged_robot.py#L409)，PetBot不照搬其步幅和只依赖平均奖励的升级判据。
4. **训练曲线与动态转换**：前进、后退、原地左右转验证后，再覆盖速度×转向组合、加减速、反向和停止。使用经实测确定的联合指令范围，高速行驶时可以降低急转幅度；保留轮速/力矩余量用于平衡。每阶段用独立场景检测不倒、响应方向/幅度、刹停和停车，而非旧瞬时精度。
5. **单独扩大运动中接管范围，最后联合验收**：两轮跑得快不等于高速四轮接管已解决。通过真实四轮驾驶形成更高初速度、角速度和控制历史，再切入起立，允许必要减速但不要求先停下；随后两轮遥控、落地及反复接管一起回归。起立世界航向与MuJoCo已暴露的交接/重复起立问题仍须处理，不可被扩速成功掩盖。

下一步合理优化目标是扩大稳定可用的速度/转向范围，而非继续把低速误差压得更小。课程、范围和控制能力是当前直接相关的调整；RMA/域随机等机制不能替代对高速任务本身的训练，后续按跨引擎与实机需求引入。
