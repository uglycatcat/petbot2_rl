# 两轮遥控验收口径复核（2026-10-26）

**仅分析第十五批现有轨迹；本次复核时训练保持暂停，后续已获稳定优先实施授权。没有修改策略、奖励、数值阈值或启动仿真。后续用户于同日确认：稳定优先，允许降低两轮速度/转向幅度，当前严格精度高于需求；具体数值标准尚未实施，见[稳定优先方案](upright_stability_first_plan_20261026.md)。以下保留本次口径复核证据。**

## 判断

现有瞬时联合合格率适合保留为严格精度诊断，但不宜作为“是否已具备可用两轮遥控”的唯一结论或下一轮唯一优化目标。0/384表示没有回合满足指定瞬时容差占比，不表示机器人完全不响应遥控。当前数据支持优先校准评价时间尺度和功能含义，尚不足以证明数值阈值在物理上不可达到，或所有波动都是平衡必需。

理想倒立摆可以稳定在平衡点，持续晃动不是普遍物理定律；实际轮式倒立摆的姿态修正、扰动和传动间隙可以导致平移速度波动。PetBot还有可动车架，简单倒立摆只能提供定性参照，不能给出本机可行精度。转向误差也不能全部归因于俯仰平衡。参考：[MIT倒立摆稳定控制](https://underactuated.mit.edu/acrobot.html)、[Yamakawa，IFAC 2011，轮式倒立摆轨迹跟踪实验，第6节](https://skoge.folk.ntnu.no/prost/proceedings/ifac11-proceedings/data/html/papers/0526.pdf)。

## 当前严格口径

`tools/analyze_cycle_quality.py`使用两轮阶段进入0.5秒后的有效样本，每60 ms采样一次，瞬时速度与原始遥控指令比较：

- 前向绝对误差小于`0.005 + 0.25 × |v_cmd|` m/s。
- 转向绝对误差小于`0.015 + 0.25 × |yaw_cmd|` rad/s。
- 两项必须在同一采样点同时满足；至少20个有效样本，且联合满足比例≥80%，该回合才算跟踪合格。
- 完整质量另需完成交接、平衡样本占比≥90%。正式跟踪统计不为每次换令另设响应宽限。

零指令允许前向误差5 mm/s、转向误差约0.86°/s；最大前向指令0.05 m/s时容差0.0175 m/s，相当于指令的35%。因此不能笼统称“全部容差都特别紧”。问题在于瞬时量、联合占比、换令瞬态和回合二值化共同决定结果，而这些具体工程门槛尚未由用户的遥控体验需求标定。[需求基线](current_scope.md)仍明确具体可行域与验收阈值需实测确定。

## 同一策略、轨迹和容差下的时间尺度对照

第十五批B六个种子终局，独立30秒遥控评估共384回合。没有重跑策略，也没有放大误差容差。

| 测量口径 | 全部有效两轮段联合通过 | 排除每次换令后0.6秒的联合通过 |
|---|---:|---:|
| 瞬时速度/角速度 | 0/384 | 1/384 |
| 位姿差分运动量，120 ms时间常数平滑 | 266/384（69.3%） | 356/384（92.7%） |
| 位姿差分运动量，过去300 ms平均 | 270/384（70.3%） | 360/384（93.8%） |

后两行是诊断，不是新的完整任务成功率；测量由瞬时速度改为位姿变化产生的平均运动量，既改变时间尺度也改变测量方式。允许换令响应时间也必须同时检查延迟和超调，不能直接删掉困难片段。未进入两轮的回合保留在384的总分母中。

383个有足够两轮采样的回合，瞬时联合满足比例均值60.9%、中位数61.6%、最大77.6%；全部低于80%便被折算为回合合格率0。这解释了二值结果为什么掩盖程度差异，但不证明只需稍微下调门槛。60 ms记录也无法辨认全部2 ms物理步波动，不能据此把快速误差全部解释成必要的平衡动作或确定其频率来源。

## 停车位移与真实异常

从同一批B轨迹提取574个原始前向/转向均为零、换令后至少0.6秒、连续记录至少1.02秒的片段。片段平均2.71秒，不是574次独立长时停车测试，也不包含发出停车指令到稳定前的制动位移。

相对于各片段第一个采样点，最大水平位移中位数4.45 mm、95分位9.20 mm；最大航向偏移中位数0.091°、95分位0.467°。多数短时停车片段的实际漂移较小，但仍有重要尾部异常：

- B43/env16：2.52秒内位移1.274 m，属于已记录的失稳越界回合。
- B44/env54：2.88秒内位移0.254 m，最终完成交接，但停车控制明显不好；不能仅用流程成功掩盖此类异常。

左右转及曲线仍有真实偏差；第十五批较宽范围（速度/角速度/车架初态同时扩大）交接仅223/384。因此平滑诊断高分不能推出遥控目标已达成，更不能代表更大速度范围、外部控制器或实机已验证。

## 建议的讨论和实施顺序

1. **先对齐验收，再决定训练架构。** 保留原始严格分数用于历史比较；先明确可用遥控允许的稳态偏差、响应延迟、停车漂移和晃动幅度，不能仅凭0%就推断必须重构策略或拆分训练。
2. **流程与稳定性作为必要门槛。** 运动接管、持续后轮支撑、前轮落地和交接之外，单独约束失稳、持续跑偏及异常高速；不允许用平均跟踪成绩补偿严重异常。
3. **功能跟踪按实际运动衡量。** 对照短时间窗平均运动、稳态偏差、换令延迟/超调、停车漂移，并单独覆盖直行、左右转和曲线。200–300 ms窗口只可作为待校准候选；窗口长度不能为了高分任意加大，指令与响应的时间口径必须一致。
4. **瞬时波动独立评价。** 保留瞬时误差、姿态摆幅、角速度/加速度峰值和动作连续性，避免滤波隐藏抖动。精度和平滑分项不必被压成一个全有或全无的成功率。
5. **确认口径后才映射到奖励和范围课程。** 当前`instant_tolerance`奖励同样强调瞬时误差，但相对的是执行指令；离线验收相对原始遥控。应一并核对，不能只换报表或在旧目标上继续堆训练。原先关于冻结基线/有界修正可能约束学习的判断仍是待验证假设。

本次分析结论是“当前严格联合率不宜独占优化优先级”，不是确认356/384已达到新的任务标准。后续用户已确认放宽精度、稳定优先，具体验收实现、奖励和训练安排按[稳定优先方案](upright_stability_first_plan_20261026.md)继续讨论；最新执行授权与实际状态见[当前交接](current_handoff.md)。
