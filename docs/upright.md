# upright_rl_demo 起立任务

## 当前需求（2026-10-22再次确认）

与recovery_agile_01独立推进，项目名称不变。目标从静止起立扩展为正常行驶中随时接管、平滑起立、后轮支撑下继续遥控行驶。

接管初态限定四轮均接触地面的正常行驶，不包含摔倒恢复。覆盖前进、后退、转向、原地转向以及左右相同的任意允许车架角度；速度和角速度的覆盖范围须在平台实际可达范围内标定，不能把所有极限组合视为都可立即起立。用户不要求预先刹停；起立期间允许必要的速度调整，目标是切换平滑并继续移动。不要求回到接管位置，也不要求追回起立过渡期间相对原始指令轨迹的偏移；稳定后从实际位置与朝向继续遥控。

起立完成后支持前进、后退和左右转向。遥控接口与初始速度范围由实现方选择便于训练的方案。车架仍输出位置目标，两侧共用；轮子仍输出速度，转向要求左右后轮独立，因此拟采用共享车架位置、左后轮速度、右后轮速度三路动作。头耳维持初始位置目标。

### 已确认的过渡期遥控方案（2026-10-19）

用户已确认：策略全程接收前后线速度及偏航角速度命令；起立时在可达加速度、转弯强度与平衡余量内平滑执行，允许暂时跟踪误差，不要求瞬时准确执行任意突变指令。稳定后由同一策略继续倒立摆平衡与正常遥控，不切回普通四轮驾驶控制器。指令限速/限加速度不能代替实际可行域验证，也不能用无限延迟掩盖跟踪失败。

该方案已获实施授权，效果仍待验证。应通过真实滚动形成一致的机身/关节/接触初态，在运动中随机切入；交接需继承实际关节目标、轮速及观测历史，避免默认零动作和历史清零造成目标突跳。训练覆盖起立前后命令变化，分别评估起立成功率、速度/转向跟踪、轨迹偏差、速度跌落、动作与加速度变化及进入稳定支撑时间。

## 移动起立完整任务契约（2026-10-22用户确认）

交付同一套策略，完成四轮行驶中接管、平滑起立和后轮支撑下的倒立摆平衡与遥控运动，不在起立后切回普通四轮驾驶控制器。遥控输入为前进速度与转向角速度；策略控制对称车架位置和左右后轮速度，支持起立期间及稳定后的差速转向，头耳维持初始目标。

- 接管继承实际运动状态、车架构型和控制历史，不将停车作为起立前置步骤。允许为起立和平衡短暂减速、加速；不要求实际速度始终非零。
- 起立期间持续接收新指令，包括转向和反向指令；经平滑与加速度/转向限制执行，允许有限延迟和跟踪偏差，以平衡为优先，不冻结指令或要求瞬时精确跟随。
- 稳定后仍由同一策略维持两轮支撑并执行前进、后退、转向和停车；零速度命令是后轮支撑下停稳，不是落回四轮。
- 起立后从实际到达的位置与朝向继续响应遥控，不强制追赶从接管时刻积分原始指令得到的假想轨迹。过渡位移、朝向偏差、时长及动作平滑性仍单独统计和限制，不通过重置目标隐去误差。过渡退出只能由真实稳定条件与时限管理，不能反复重置参考逃避跟踪。

具体可行域、过渡时限、平滑幅度及验收阈值需实测确定。分阶段/课程训练是学习安排，最终仍需用完整运动接管与持续遥控任务独立验收。当前第四批固定14dca2d仍采用旧原始轨迹奖励与判据；本契约用于下一版实现，不中途修改运行副本，旧结果与新口径不能直接混比。

## 行为依据与实测

`jump_demo` 是关键行为参照：先让前轮离地，再维持后轮支撑平衡。它不是模仿轨迹、不作为训练数据；不要求RL复制先前进再后退的动作表。2026-10-16已在服务器anna用户下配置uv/MuJoCo环境，运行原控制器12秒并检查曲线和渲染关键帧：约2.522秒进入平衡，末段前轮中心约0.19m；最大水平偏移0.405m、末态偏移0.228m。因此它证明抬升/平衡，但没有完成回位目标。

首版GPU0/1双种子各2048×1500已经结束，6次评估稳定成功均0/64，详见[首版结果](upright_first_results.md)。第二版基于实际复现设计两阶段奖励、回位硬判据、窗口稳定检测；详见[第二版设计](upright_v2_design.md)。第二版两种子各2048×3000及8次检查点评估已结束；完整成功、阶段2及离地事件均0/64，未学会任务。奖励上涨仅来自准备阶段，std降至约0.02。终局与后续优先级见[第二版训练记录](upright_v2_training.md)。旧固定运行版本保留。
