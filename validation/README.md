# MuJoCo 验证记录

2026-10-27，源模型指纹 `b82c59d…`，MuJoCo 3.16.0、PyTorch 2.10.0 CPU，依赖以 `uv.lock` 为准。采用源 MJCF、力矩上限和伺服增益，没有改模型或引入参考起立动作。测试的是仿真推理，不是宿主机训练。

## 工程对齐

[port_parity.json](20261027/port_parity.json)：13 个源文件 SHA 校验，9 个纯逻辑模块字节一致，4 个控制类/函数去除 Isaac 依赖后 AST 一致；35 个阶段/时钟/随机状态的 58 维观测与原函数误差为 0。航向角速度与独立积分差 0.00031 rad/s；静止支撑力 16.211423 N，对照重量 16.211417 N；执行器力矩上限与按键按下/重复/释放检查通过。

网络导出在训练容器 CUDA 上用 1024 条输入对照外层策略、平衡修正和基础网络，最大误差均为 0。GLFW 窗口通过 Xvfb/OpenGL 创建、绘制、运行和退出检查；实际遥控体验仍需桌面操作者确认。

| 固定场景 | 实测 |

完整原始摘要及 trace SHA 见 [scenarios.json](20261027/scenarios.json)，包括 r43 和原父参考的失败，不删除不利结果。相同初态/指令的渲染复现不当成新增独立样本。全部为开发诊断场景，不能计算成泛化成功率；180 秒保持也不覆盖所有长时遥控输入。

实际轨迹存于工作区 `artifacts/s2s_validation/` 以及 `artifacts/s2s_initial_*`，不提交大量逐帧文件。源训练/评估和父策略仍在 `demo_project/runs/`，没有迁移或删除。二次起立失败可能与起立仍使用世界坐标、进入分布或部署重接管有关；目前只是待诊断假设，不能直接归因。

## 成熟度判断

已有可复现的训练、导出和包含全部反馈环的跨引擎控制器，默认低速场景能够完成长时两轮遥控与起落闭环。仍需处理跨引擎落地交接、重复接管及初态/航向覆盖，之后再决定正式训练项目迁移。当前定位为可体验、可诊断的原型，不能认定仅调整超参数即可成熟。
